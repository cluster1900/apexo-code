# Native background Shell

Status: shared backend integration, CLI and rebuilt packaged Desktop acceptance passed. The Process manager UI is integrated and its shared window/performance acceptance is complete. Monitor is a separate follow-up on the same owned process lifecycle.

## Contract and ownership

Native `bash` preserves its existing foreground behavior when new background options are omitted. `background: true` returns after successful spawn. `block_until_ms` opts into a bounded foreground wait and promotes the same running process when that wait ends; zero returns after spawn. Both forms require a nonempty description and cannot be combined. Existing execution timeout remains separate: default 120 seconds, maximum 600 seconds. The new wait budget is also bounded at 600 seconds. This is an explicit Apexo bound, not a claim of identical installed defaults or unlimited background lifetime.

A shell receipt has a canonical `proc_` identifier and a private immutable invocation, Session creation proof and process owner. It is not a child Session or a Task ID. `process_output` reads retained state, `process_wait` waits without killing on timeout, and `process_cancel` cancels and joins. Canonical permissions still run before process mutation; external working directories require `external_directory`. Selected command sandbox policy is captured by the real AppProcess/CommandSandbox path. Live output removes only the exact private launcher handshake; final confirmation still runs.

Separate passive native endpoints list, read, wait and cancel under `/api/session/:sessionID/process`. Cancellation is bodyless. Reads and HTTP waits do not start providers or consume a model completion notice. Foreign ownership returns 404. A bounded model wait consumes a terminal notice; cancellation suppresses it. Current still-starting receipts are hidden until spawn succeeds. Output is bounded to one MiB of complete UTF-8 text, with an explicit truncation flag.

BackgroundJob remains the existing scoped process owner. Its metadata is used only for captured lifecycle registration; private receipts authorize access. Session deletion and Location shutdown join real processes and terminal storage. Unfinished receipts after application restart project `interrupted` with `process_restart`; reads, waits and public Session continuation never replay the command. No second executor, fake user prompt or legacy prompt loop is introduced.

Terminal storage precedes completion readiness. Delivery uses the existing ordinary Session coordinator at its idle boundary, so active parent work completes first. Tickets belong to the exact Session incarnation/current process and accepted Stop generation. Managed children, stored active Goals and captured Goal attempts are rejected before process receipt/spawn. Ordinary paused Goals without an active captured attempt remain ordinary Sessions. Pending Plan approval stays ahead of all completion consumption in the composed runner; a real native HTTP/provider regression verifies that the pending question survives process settlement without provider work until explicit approval.
