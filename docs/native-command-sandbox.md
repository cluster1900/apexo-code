# Native command sandbox

This bounded G02 slice is integrated with CLI and rebuilt Desktop backend acceptance. Creation controls, broader enforcement and final aggregate gates remain open.

Native Session creation accepts `commandSandbox: off | workspace | read-only`. A new root defaults to an explicit stored off policy. Existing IDs adopt immutable stored authority; conflicting explicit selection fails. New trusted children inherit through an opaque parent capability, with policy and Created projection committed in the same transaction. No policy is inferred from mutable metadata or repaired at execution time. The migration seeds off only for pre-existing Sessions with a unique valid durable Created proof. Unverifiable historical Sessions remain unavailable.

On macOS, selected policies apply to native Bash and its descendant processes through Apexo's AppProcess and Permission services. Workspace mode permits writes inside the workspace and a private temporary directory; read-only permits only private temporary writes. Both deny networking, including loopback, and protect control paths and their ancestors. Arguments remain opaque, environment is replaced with fixed PATH and private HOME/TMPDIR, and caller file descriptors are not inherited. An absent trusted launcher confirmation fails closed. Cancellation joins the owned process group.

This is path-access enforcement. Pre-existing workspace hardlinks can modify an inode also named outside the workspace; unsandboxed external writers remain a limitation. In-process file tools, Hook/MCP/LSP hosts and whole-agent execution are outside this slice. Linux enforcement, Config defaults and richer reference profiles remain open. Confined commands require an absolute shell; separate stdout/stderr capture does not preserve cross-stream ordering.

Passive `GET /api/session/:sessionID/sandbox` distinguishes stored policy, unchecked/available backend and latest confirmed completed execution. It launches no process and performs no provider work. Receipts are process-local and reset on restart. A receipt does not assert current enforcement. Missing policy omits network and reports a typed failure; a missing Session remains404.

Compatibility prompt/shell/command execution requires a verified off policy. Confined compatibility forks are rejected before copying because this slice does not implement trusted root policy cloning. New legacy roots store explicit off at creation, and legacy children inherit their real parent's policy. This prevents changing API paths from silently bypassing selected native command enforcement.
