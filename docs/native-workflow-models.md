# Native Workflow Child Model Selection

This slice is integrated and verified in live CLI and the coordinated packaged Desktop backend.

A declarative Workflow stage accepts an optional canonical `model` reference: `{ providerID, id, variant? }`. A Rhai `agent` call or each `parallel` entry accepts `model: "provider/model"`. Omitted selections inherit the Workflow parent. Unlike the reference's configured bare model names, Rhai selection uses Apexo's provider-qualified model parser.

Explicit selections use the ordinary native Session model resolver before child creation. Missing models, unsupported APIs, and unavailable variants fail without creating that child or calling its provider; there is no silent fallback. Model selection does not alter the parent agent, inherited permissions, read-only role filtering, or Workflow usage accounting. Credential resolution may refresh remotely, so preflight runs before child mutation admission. Parent execution still owns cancellation, and the short child lease rechecks parent existence before creation. Provider execution remains inside native child Session ownership and outside mutation leases.

Explicit selections participate in the existing immutable stage/task hash. Changing the model or variant under an already reserved task key fails replay validation. A resumed attached child must still have the expected explicit model. Completed child receipts persist without starting another provider call on restart. Agent-budget pauses retain the original selections for explicit resume.

The pinned reference revision `2bdd1d6a6369de0e8c68132ea4539e9abd9e14a8` exposes per-child model selection in `xai-workflow/src/host.rs` and forwards it through the Workflow host. Installed Grok 1.0.52 comparison confirmed an explicit child model reached the alternate configured provider model: two checks passed, with one child call and three total requests including ancillary work. This is comparison evidence only.

Isolated Apexo validation passed Core and Apexo typechecks. After integration, the focused and native HTTP/lifecycle suite passed 16 tests with 100 assertions across six files. Both the isolated draft and integrated live `bun script/grok-workflow-model.mjs cli` passed five checks with five provider turns, covering mixed parallel models, inheritance, native variants, unavailable selections, complete-panel budget resume, actual token totals, and receipt persistence. `bun script/grok-workflow-model.mjs desktop` passed the same five checks with five provider turns against the coordinated artifact. This verifies packaged backend behavior, not visual UI rendering. The first live CLI attempt stopped before backend readiness while the legacy SDK generator temporarily removed its generated types module; no Workflow scenario ran. After generation completed, the live CLI passed all five checks. This shared-filesystem race is recorded in [BUG-20261014-242](testing/test-fixtures/concurrent-sdk-generation-and-typecheck.md), not as a Workflow product defect.

The separate [Rhai effort draft](native-workflow-effort.md) documents its own implementation and verification boundary; schema-correction retries are covered by their later dedicated slice. Canonical stage variants use existing native variant semantics; they are not a new reasoning-effort contract.
