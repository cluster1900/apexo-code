# Desktop Runtime Profile

Desktop General settings now exposes the bundled local server's Apexo and Grok Build tool profiles in both settings layouts. A selected preference is persisted through native IPC. The active label remains the launch-time snapshot; a pending notice explains that the next Desktop launch applies the preference. Selection does not interrupt sessions or restart the running backend. Background-service/V2 Desktop shows an unsupported explanation instead of claiming an active local profile. Remote servers retain their own configuration.

This selects Apexo's tool contract. It does not replace the execution engine with the official Rust Grok runtime. Official `grok 1.0.52 (0920c8169e27)` help was inspected, together with source revision `2bdd1d6a6369de0e8c68132ea4539e9abd9e14a8`: `xai-grok-tools/src/versions.rs` distinguishes the `GrokBuild:run_terminal_cmd` namespace, and the builder/tool taxonomy uses `run_terminal_cmd` as the terminal contract. The native acceptance checks that Apexo's default profile advertises `bash`, while Grok Build advertises `run_terminal_cmd`. This contract comparison is not a claim of runtime equivalence or complete official feature parity.

The pending-state screenshot was visually inspected: active Apexo and next-launch Grok Build are distinct and fully legible.
- Full `bun script/grok-profile-desktop.mjs` acceptance passed on Bun 1.3.14 after the fixture corrections and integrated layer fix. Native UI selection, disk persistence, unchanged pending-provider tools, owned relaunch, applied Grok contract, and CLI manifest/provider comparison all passed. The noninteractive CLI intentionally omits the three question/plan tools denied by `run.ts`; the fixture asserts exactly those differences and exact equality for all remaining contracts. See [BUG-20261014-042](testing/test-fixtures/profile-cli-stdin.md), [BUG-20261014-043](testing/runtime/profile-cli-session-execution-layer.md), and [BUG-20261014-048](testing/test-fixtures/profile-interactive-tools.md).

The fixture uses isolated app data, XDG directories, test home, random ports, and its own Electron children. It never closes or relaunches a user-owned app or server. Its final check compares the native provider's tools with the permitted real CLI `--profile grok-build` manifest and compares that complete manifest with the corresponding provider request.

## Localization review

Configuration and desktop vocabulary were cross-checked with [Firefox's maintained Simplified Chinese preferences corpus](https://github.com/mozilla-l10n/firefox-l10n/blob/main/zh-CN/browser/browser/preferences/preferences.ftl), [Mozilla's localized developer edition](https://www.mozilla.org/zh-CN/firefox/developer/), and [Microsoft's localized runtime documentation](https://support.microsoft.com/zh-cn/access/download-and-install-microsoft-365-access-runtime). Native-speaker review remains useful for this product-specific label; only English and Simplified Chinese received dedicated copy in this feature.
