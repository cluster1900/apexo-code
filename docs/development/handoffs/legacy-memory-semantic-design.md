# G05: Optional legacy semantic retrieval and flush deduplication

Status: design only at the 2026-10-15 review pause. No semantic implementation or installed semantic success is claimed. Fixed reference is `2bdd1d6a6369de0e8c68132ea4539e9abd9e14a8`. Resume only after user review.

## Verified scope

The Grok source constructs `MemoryBackendImpl` only for legacy storage (`xai-grok-shell/src/session/acp_session_impl/spawn.rs:959`). V2 uses topics/observations and its own context/maintenance paths. This is not a missing V2 vector feature. Its public documentation says only API embeddings are currently supported; comments listing `local`/`auto` are not evidence of implementations.

`xai-grok-config-types/src/memory.rs:242` defines `memory.embedding.provider="api"`, `model=None`, dimensions1024. Unset/empty model means FTS-only. Search defaults are vector_weight0.7/text_weight0.3, six results/min_score0.7. `xai-grok-memory/src/search.rs` merges BM25 with optional vector KNN, floors shared results at their full FTS score, preserves full FTS-only scores, then applies existing decay/source/access factors and MMR. Vector-only scores use vector_weight. The actual distance conversion is clamp(1-L2/2), including flush dedup, despite comments calling it cosine.

`embedding.rs` sends OpenAI-compatible POST /embeddings with model/input/dimensions, batches32, and up to3 attempts for transient failures. `backend.rs` binds credentials to the endpoint, refreshes changed/deleted chunks, embeds missing chunks and queries. Failures degrade to FTS-only. `flush.rs:177` checks top3 neighbors and suppresses a write only when similarity is strictly greater than semantic_dedup_threshold (default0.92); unavailable/failed embedding or vector search permits the normal write. This is distinct from exact transcript/marker deduplication.

Apexo already implements legacy FTS/BM25, source weights, access boosts, temporal decay, staleness hints and token-overlap MMR in Core MemorySearch. These are not gaps. Missing pieces are optional embedding configuration and authenticated transport, a content/model-bound vector cache, hybrid candidate merging and semantic legacy-flush suppression. Native Sessions pinned to legacy and the compatibility legacy surfaces should share the same Core mechanisms.

The existing isolated installed1.0.52 legacy probe requested memory_v2.enabled=false but observed V2 artifacts. It proves isolation and effective-backend mismatch, not a working legacy/vector path. Before attempting an installed semantic scenario, inspect effective backend/tool availability; do not force a disabled path or label a V2 tool run legacy. Source and independent Apexo proof remain separate if the installed release cannot expose legacy.

## Proposed native architecture

1. Add optional embedding settings and search weights to ConfigMemory.Info/Search, plus Flush.semantic_dedup_threshold. Default behavior remains lexical. Use an explicit provider/model reference; an unqualified embedding model can use the captured Session provider only when that provider is the configured credential/endpoint owner. Support the API transport first; reject unsupported local/auto configuration rather than imply an implementation.
2. A Location-scoped MemoryEmbedding service resolves the configured provider through the existing Catalog and Integration connection services. Follow SessionRunnerModel's credential resolution, without treating the embedding model as a language-model turn. Endpoint/provider/model/dimensions form a stable non-secret identity. Never persist keys or forward a Session key to an unrelated override endpoint. Use the existing HTTP transport/abort ownership, bounded request/response sizes, batch32, finite exact-dimensional vectors, one indexed result per requested input, and bounded transient retries. Malformed/partial/duplicate-index output is never cached.
3. Extend the existing generation-specific legacy search.sqlite, not the Session database or V2 store. Cache each vector by canonical scope/path, chunk start/content hash, embedding identity and dimensions. SQL transactions replace changed chunks and their vectors together. Existing forget/clear/consumed-source cleanup and external edits invalidate matching vector rows; generation-specific database names fence stale in-process instances after clear. This is Apexo-owned indexing, not imported Grok schema.
4. Perform authorized sync-on-search embedding in the existing MemorySearch owner. No new background executor or passive restart sampling. Revalidate current/captured source permission, source identity/hash, maintenance generations, Session Created/mode/Agent and endpoint identity before sending content and after awaits, before caching or returning results. An interrupted native worker joins its pending request before releasing ownership. No network work while holding SQL transactions or publication locks.
5. Use a bounded exact numeric KNN scan over cached vectors initially (SQLite rows streamed in pages, fixed candidate heap), avoiding a new native extension requirement. This is real vector ranking, not token overlap renamed semantic search. Preserve existing lexical candidates and scoring. Merge by exact chunk identity with the reference scoring rules, then reuse current decay/source/access/MMR. Expose a truthful content-free retrieval mode/fallback diagnostic rather than claiming hybrid when embeddings fail.
6. Legacy flush invokes the same Core semantic check after validating the model's accepted Markdown and before its existing fenced publication. Snapshot the authorized indexed candidates; resolve/embed once under the existing operation owner. A positive match must still have exact current bytes and read authority at commit. Record the content-free duplicate decision and exact dependency hashes with the existing durable operation publication proof. Only then suppress the body and settle the original source marker/receipt. Permission change, deletion/clear, different Agent, stale snapshot or cancellation cannot create a duplicate decision or suppress new content. Provider failure falls back to the normal validated write, never false suppression. Exact retry must not re-embed or re-sample a durably settled decision.

## Required proof before acceptance

A query with no shared lexical terms must retrieve a known semantically related chunk only when embeddings are enabled. Compare lexical-only, hybrid, invalid/missing provider and malformed/dimension-mismatch responses. Verify no credential crossing to another local endpoint. Hold embedding responses while revoking source permission, switching Agent, clearing/deleting, changing a file or replacing it with a symlink; no leaked second request, stale cache commit or returned content. Verify content/model/dimension/endpoint changes invalidate only corresponding cache data. Exercise concurrent scopes and exact repeated operations. Semantic duplicate/nonduplicate/boundary-threshold checks must inspect actual persisted file bytes and request counts, including crash after durable duplicate decision and explicit retry without another embedding request. Run real CLI, rebuilt Desktop, browser and both terminals where user-visible outcomes change; retain installed effective-backend limitation honestly.

## Supported reference entrypoints

Pinned `xai-grok-pager/src/memory_cmd.rs` exposes only `memory clear`, not a standalone `memory search` command. Semantic retrieval is reached through the legacy `memory_search` model tool and legacy initial/post-compaction context injection. The tool reports Memory unavailable when no backend is installed. A meaningful isolated runtime probe therefore must first prove an effective legacy Session and its actual offered tool catalog, then invoke that real tool with a provider-local embedding endpoint. Inventing a CLI search subcommand or forcing V2 into the legacy backend would not establish supported reference behavior.
