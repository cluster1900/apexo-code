# Native language-server capability

## Architecture and contract

Apexo Core owns language-server processes, JSON-RPC request lifecycle, permission checks, Location placement, plugin activation, and native tool execution. The generic `vscode-jsonrpc` library handles wire messages; Core does not import the legacy Apexo package or a Grok runtime.

The native `lsp` tool supports `goToDefinition`, `findReferences`, `hover`, `goToImplementation`, `documentSymbol`, and `workspaceSymbol`. Apexo keeps its own `filePath` and 1-based UTF-16 line/character contract, converting at the protocol boundary. Workspace symbols use a query and require project-wide read and LSP permission. Document queries resolve canonical paths, reject relative and symlink escapes, require explicit external-directory approval for absolute external files, then read permission and LSP permission before transmitting file contents. Documents must be regular UTF-8 text, without NUL bytes, at most 2 MiB.

Trusted installed plugin LSP definitions are prepared as candidates. Installing or enabling a plugin does not activate it in an existing Location until apply/reload succeeds. Candidate initialization and liveness validation precede synchronous publication alongside MCP, agents, commands, skills, and the bundle generation. A failed candidate preserves the previous active generation and connections. Active requests hold the existing Location runtime guard. Scope disposal, request cancellation, candidate rejection, and generation retirement close owned process groups, including descendants.

Configured stdio servers use command/arguments, environment, initialization options, settings, extension-to-language identifiers, and bounded startup/request timeouts. Host configuration overrides the plugin layer. Unsupported transports and workspace overrides remain explicitly unsupported instead of being advertised as active. Opt-in automatic restart and configurable startup/shutdown bounds are described in the policy section below. Native LSP does not install language servers or edit files; the client refuses server-initiated workspace edits. Initial Location creation may initialize configured servers. Repeated `GET /api/lsp` calls only inspect current state and never retry or start model work. Connection loss emits canonical `lsp.updated` with Location metadata.

Native-only policy validation is requested by PluginBundleState; compatibility discovery retains its existing parser behavior.

The status contract includes server identity/root, `connected`, `disabled`, or `failed`, supported operation identifiers, and an optional sanitized failure. App synchronization selects native `/api/lsp` only for the native protocol and retains the compatibility route on mixed/legacy servers. Disabled state is intentional; failed state appears as a nonblocking warning.

## Pinned plugin configuration field audit

The pinned reference `LspServerConfig` struct is the field inventory; installed inspection independently confirmed extension mapping and command discovery. This table distinguishes actual consumption from explicit capability rejection. It does not imply every reference transport or restart policy is implemented.

| Reference field / aliases | Native behavior |
| --- | --- |
| `command`, `args` | Spawn owned stdio process; expand plugin-root placeholders and resolve dot-relative command paths against the installed bundle. |
| `transport` | Omitted or `stdio` supported; `socket` and other non-stdio values explicitly unsupported. |
| `env` | String environment mapping with plugin-root expansion. |
| `extensions`, `extensionToLanguage`, `extensionToLanguageId` | Preserve both dotted extension selectors and language identifiers for document-open notifications. |
| `initialization_options`, `initializationOptions` | Object initialization payload sent during initialize. |
| `settings` | Object settings returned to server workspace/configuration requests. |
| `startup_timeout`, `startupTimeout` | Nonnegative millisecond startup bound, default 15,000; maximum 2,147,483,647. |
| `workspace_folder`, `workspaceFolder` | Explicitly unsupported override; active Apexo Location remains authoritative. |
| `workspace_open`, `workspaceOpen` | Explicitly unsupported solution/project extension requests. |
| `restart_on_crash`, `restartOnCrash` | Opt-in crash recovery; false/omitted disables automatic restart. |
| `shutdown_timeout`, `shutdownTimeout` | Nonnegative graceful-handshake bound, default 5,000; maximum 2,147,478,647, reserving five seconds for bounded cleanup. |
| `max_restarts`, `maxRestarts` | Unsigned 32-bit lifetime attempt budget, default three; zero prevents recovery attempts. |

Apexo additionally supports a positive `requestTimeout`/`request_timeout` in plugin definitions; it is not claimed as a reference field. The native structured configuration stores supported timeouts under `timeout` and language mappings under `languageIds`. Focused adapter tests exercise all three extension spellings, both initialization/startup spellings, and the remaining unsupported canonical/alias policies through real plugin reload. New restart/shutdown aliases also have focused validation tests. Each failed reload preserves the working prior connection. Compatibility discovery does not opt into the native capability rejection.

## Crash recovery and bounded lifecycle policies

The pinned reference `lsp/config.rs`, `restart.rs`, `dispatch.rs`, and `client.rs` define the policy contract: restart is disabled by default; the default restart budget is three attempts over a server monitor's lifetime; failed starts consume attempts; a successful restart resets the backoff to one second but does not replenish the budget. Consecutive failed starts double the delay up to 30 seconds. Only servers that initialized successfully are eligible for automatic recovery. The isolated installed Grok Build 1.0.52 probe passed eight checks with three local provider calls, including zero/default-disabled behavior, successful and failed-start budget consumption, initial startup timeout, and no respawn after Session close. Session close killed its process promptly, so that observation does not independently verify its graceful-shutdown timeout; that contract is source-backed.

Apexo owns recovery in Location-scoped fibers. A connection identity fences candidate publication and failure updates; a Deferred barrier registers a worker before it may complete, including the zero-budget case. Recovery acquires the existing Location runtime guard and waits while ordinary work is active without spending an attempt. Successful recovery updates only the affected connection and publishes canonical Location-scoped `lsp.updated`. Status reads remain passive. Exhaustion is a sanitized failed status; a successful explicit plugin reload creates a fresh budget.

Manual reload parks recovery and interrupts/joins pending recovery candidates before acquiring the Location mutation guard. A failed or interrupted manual reload preserves the prior connection and resumes its existing recovery eligibility/budget. Location disposal fences callbacks, cancels workers, and closes all child scopes; retirement closes process groups and descendants. Startup failure skips the graceful shutdown handshake because no initialized LSP session exists. Shutdown bounds the complete shutdown/exit handshake, then performs bounded process cleanup. Timer limits deliberately reject values that cannot safely fit the JavaScript timer range, instead of silently converting them to a very short timeout. Duplicate canonical/alias spellings for the new policy fields are rejected.

Automatic recovery never rereads or retransmits documents. The next tool call repeats the existing filesystem/permission checks and sends current authorized content. This intentionally avoids the reference monitor's automatic disk reread/replay, preserving Apexo's read and external-path permission boundary. Workspace roots/overrides remain unchanged and server-initiated file edits remain denied.
