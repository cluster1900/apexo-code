# Native Memory tools and passive management

This slice implements Memory inside Apexo's native Location tool registry and Session lifecycle. It does not call the compatibility Session prompt loop, run Grok, extract transcripts, schedule Dream, or add a second model executor.

## Contract

Memory remains off by default. The existing MemoryPolicy profile, explicit process-disable precedence, configuration, durable backend selection and per-Session mode determine availability. Legacy Memory advertises `memory_search` and `memory_get`, plus Apexo's existing `memory` read/remember adaptation. The latter is not presented as an official Grok V2 model tool. V2 Sessions retain their curated filesystem context and ordinary file tools; these three legacy tools cannot write through a V2 selection.

The native Session API adds status/toggle, note catalog, preview and reviewed-hash deletion. Status, catalog and preview perform no provider work. Status may initialize the existing durable backend selection, but does not read note contents. Catalog and preview never import fallback workspace notes. Remember refuses when older fallback notes require explicit migration, preserving both old knowledge and the selected target. Migration, capture, flush, Dream and clear management remain outside this slice.

The routes are `GET/PATCH /api/session/:sessionID/memory`, `GET /memory/notes`, `GET /memory/note?path=...` and `DELETE /memory/note` with `{path,hash}`. They use the stored Session Location. Paths must belong to the backend catalog and pass actual canonical read/edit permissions; they are not arbitrary filesystem endpoints. Disabled/forbidden requests return 403, changed/unsupported/busy requests 409, missing resources 404, invalid input 400 and unavailable storage 503. Responses never contain private authority or credentials.

Public management refuses privately managed and historical child Sessions. Public Session metadata cannot restore their live owner's authority. Native tool settlement preserves the actual agent and captured parent permission boundary, including hard denial. Goal role filters remain authoritative. Reading or writing Memory is still tool work within the existing owned Session drain; the runner retains one explicit provider stream per provider turn.

The HTTP handler observes the process-global execution active set before status/toggle. `busy` is advisory: it is not an atomic coordinator reservation, and an independent drain may start after that observation. Enabling an observed busy, disabled Session is refused. A change affects subsequent materialization. Mode writes and tool result/write commits independently validate the Session incarnation and mode revision under a short storage fence. Disabling invalidates a pending operation's eventual commit; it does not itself promise to dismiss an already displayed permission request. Explicit Session cancellation/deletion joins owned operations. Remember also checks the existing Memory generation, so a clear completed during permission approval cannot receive the stale write.

## Verification

Shared integration passed the combined eleven-file Memory/terminal regression: 96 tests / 371 assertions, plus all 21 workspace typechecks. Client and legacy SDK generation passed, and regenerated Client output matched an isolated candidate index without changing the real Git index. Five native Memory HTTP inventory scenarios passed against 283 inventoried routes without missing or extra routes. The complete HTTP gate is tracked in the implementation checkpoint.

The shared source CLI and freshly rebuilt Desktop backend each passed four checks / three provider calls, including durable mode after actual process restart and passive catalog/preview/hash-forget. A fresh isolated installed-reference run passed the same two enabled configuration comparisons described below, with four total local provider requests. This backend acceptance does not establish Memory management UI completion. The first combined run's Memory-context deadline remains an [unresolved timing observation](testing/test-stability/native-memory-context-timeout.md), despite the unchanged isolated and aggregate passes.

Private production-source verification passed 36 tests / 229 assertions across six files: the native Memory service and pure/mixed HTTP cases, native Memory context, and existing search/catalog/workspace regressions. The native HTTP cases exercise three provider turns, native tool parts, passive management and exact-hash forget. Cases also cover hard denial, inherited parent denial, private child authority despite metadata edits, mode revisions, deletion/reuse, disable/clear during approval, non-migration of old notes, most-specific external-directory permission and aliased-home appends.

The private source CLI also passed four checks with three provider calls: default-off/passive management, native tool transcript, catalog/preview/hash-forget/disable, and durable mode after process restart without provider wake. Core, Server and Apexo package typechecks passed. Shared Desktop and generation results are recorded separately above.

The pinned Grok source at revision `2bdd1d6a6369de0e8c68132ea4539e9abd9e14a8` registers `memory_search` and `memory_get` in its legacy Memory tool module. Its `/memory` command is human management. The isolated installed comparison used two fresh configurations requesting legacy and V2, with all home/XDG state redirected and an owned disposable non-temporary repository. Both reported Memory enabled and exposed `read_file`/`grep`, without legacy Memory model tools. Both passive list calls caused zero provider calls; the two comparison prompts produced four total local provider requests. This observed installed behavior does not prove legacy tool execution or make Apexo's `memory` adaptation an official V2 tool. The reference fixture is comparison-only and never a production dependency.

Compatibility tests and installed observations are separate from native implementation verification. Capture, Dream, flush, explicit migration and additional management UI are not declared completed by this slice.
