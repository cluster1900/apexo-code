# Feedback image attachments

Status: integrated, with shared backend and generated-client acceptance. This extends [Feedback drafts](feedback-drafts.md) inside Apexo. It does not embed the reference runtime or submit an external issue.

## Product behavior

App and Desktop offer explicit file selection and image paste, thumbnails, names and removal. Selection remains visible after invalid input or a revision conflict. Mini/fullscreen Feedback uses `i` for an explicitly selected local file, `p` for an explicit clipboard image, and `1`–`4` to remove the corresponding selected image. The terminal reads only the chosen client-side file; the server never interprets a supplied local path. Saving captures bytes, so later changes or deletion of the source file do not change the saved image.

Reviewing an image-bearing draft permits blank details with a nonblank title. Export creates a self-contained HTML report with escaped title/body/filenames, image previews and per-image downloads of the exact original bytes. There is no script in the export; CSP disallows external resources and scripts. Text-only exports remain Markdown. The terminal creates new exports exclusively with mode 0600 and refuses overwrite. Images remain local: the user downloads and manually attaches them to the GitHub issue. Opening the issue form sends no image payload or local path and does not delete the draft.

## Ownership and limits

Schema permits four PNG/JPEG/GIF images, eight MiB each and sixteen MiB combined. Core validates canonical base64, MIME/signature, safe display filename and actual image decoding before writing. Apexo additionally rejects PNG/GIF canvas or JPEG SOF header dimensions whose width × height exceeds 32 × 1024 × 1024 pixels before decoding and limits all images belonging to one Session to 64 MiB. Unsupported images fail explicitly; none are silently dropped. There is no WebP, SVG or automatic resize/transcode. Original compressed bytes are retained, including GIF payloads.

`session_feedback_image` stores raw bytes separately from draft metadata, with a draft foreign key and cascading deletion. Existing text-draft limits remain independent. Lists and reviews return image metadata only. Save's optional `images` contains either owned existing image IDs or new snapshots `{ data, mimeType, fileName? }`. Omitting the key preserves current attachments; `[]` explicitly removes them. Replacing/removing images on an existing draft requires its current revision. New drafts may contain images without a prior revision. Foreign draft/Session image references and duplicate IDs fail. The transaction rechecks ownership, revision and aggregate quotas after decoding.

Both API surfaces expose `POST /session/:sessionID/feedback/:draftID/image/:imageID` (native prefix `/api`) with `{ revision }`, returning metadata plus base64 only for the current owned revision. Stale reads return conflict; removed or foreign images return missing. Draft and Session removal cascade image ownership atomically. No arbitrary user file is deleted.

The model-facing `send_feedback` schema remains text-only, including existing `draft_id` and optional revision semantics. Its real update path preserves operator attachments and still requires nonblank text details. Management APIs create no prompt/provider turn and do not invoke the model tool permission flow.

## Reference comparison and deliberate boundaries

Fixed source Git revision `2bdd1d6a6369de0e8c68132ea4539e9abd9e14a8`: `feedback_types.rs` defines four/eight/sixteen limits and MIME set; `draft_images.rs` owns snapshots; `draft_store.rs` allows image-only reviewed details; model `send_feedback.rs` has text fields only; extension `feedback.rs` places images inside reviewed `edited_body`.

`bun script/grok-feedback-images-official.mjs` ran installed Grok 1.0.52 (`0920c8169e27`) with real host-home denial, minimal environment and outbound networking limited to the exact local fixture port. Guards confirmed home denial and unrelated-port denial before launching. A real model call saved its local draft; operator extension rejected top-level images, five images and WebP, then accepted image-only reviewed details and delivered the exact PNG bytes to the fixture feedback endpoint. The reference deleted the submitted draft. These are reference observations, not Apexo test coverage.

Apexo intentionally retains its reviewed local draft and prepares a manually submitted GitHub issue. It does not copy official feedback submission, Slack routing, feedback trace upload or automatic sent-draft deletion. Database representation, Session quota and decoder bound are native choices. Windows/Linux native-window and clipboard acceptance are not established by these macOS runs. Browser clipboard grant and denial were exercised; direct positive native OS clipboard input was not exercised. Desktop uses its existing platform clipboard bridge, and native-window file selection/export passed.

## Localization

New App copy uses typed English, Simplified Chinese and Traditional Chinese keys with the existing language fallback for other locales; this is not an assertion that the whole locale corpus is complete. Existing terminal English scope is unchanged. PNG/JPEG/GIF, MiB, HTML, GitHub and keyboard legends remain technical names.

Terminology was checked against Mozilla's [zh-CN browser context corpus](https://raw.githubusercontent.com/mozilla-l10n/firefox-l10n/main/zh-CN/browser/browser/browserContext.ftl) and [zh-TW corpus](https://raw.githubusercontent.com/mozilla-l10n/firefox-l10n/main/zh-TW/browser/browser/browserContext.ftl), plus VS Code's maintained [Simplified Chinese](https://raw.githubusercontent.com/microsoft/vscode-loc/main/i18n/vscode-language-pack-zh-hans/translations/main.i18n.json) and [Traditional Chinese](https://raw.githubusercontent.com/microsoft/vscode-loc/main/i18n/vscode-language-pack-zh-hant/translations/main.i18n.json) attachment/clipboard/export phrases. Taiwan MOE's [圖片 entry](https://dict.concised.moe.edu.tw/dictView.jsp?ID=11466&la=0&powerMode=0) supports the Traditional Chinese noun. Complete manual-upload and failure sentences were reviewed in this product context; regional preference for 圖像 versus 圖片 remains a focus for native-speaker review.
