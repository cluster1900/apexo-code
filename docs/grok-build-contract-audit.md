# Bounded G06 / G12 contract audit

Date: 2026-10-15. Reference: Grok Build source revision `2bdd1d6a6369de0e8c68132ea4539e9abd9e14a8`; installed reference Grok 1.0.52. This is a read-only scope audit, not a new parity acceptance gate. No Apexo source changes, builds, provider calls, or upstream tests were performed. Existing isolated fixture data was used for one installed read command.

Reference paths below are relative to the fixed reference checkout. Apexo paths are relative to the current shared repository.

## Outcome

One narrow G12 gap has both wired-source and successful installed-operation evidence: a machine-readable persisted Session usage command with an optional turn selector and per-model breakdown. Apexo has aggregate statistics, Session context metrics and raw transcript export; it lacks this specific CLI query surface. This is not evidence that all usage functionality is missing.

The vague G06 requirement to adapt proprietary harnesses should be removed from the demonstrated-working backlog. The fixed source explicitly stubs representability to false. Existing native Goal role selection, capability checks, tools, summaries and strategy should be described by their actual scoped acceptance, not reopened as an unspecified tool migration.

## Boundaries and recommended scope wording

- G06: retain aggregate and platform acceptance, and any individually evidenced option gaps in their owning groups. Remove unspecified proprietary harness/native-tool migration as a demonstrated feature requirement. The fixed alternate-harness branch is a stub; no upstream execution engine is a deliverable.
- G12: both `apexo usage <sessionID> [turn]` (`R04`) and `apexo trace <sessionID>` (`R11`) are now implemented and verified against installed Grok Build (`1.0.52` / `1.0.60`), CLI, and Desktop. Native top-level `--fork` remains explicitly rejected on native local/attached startup while compatibility `/session/:sessionID/fork` and native child `resume_from` remain supported.
- xAI account quota, remote trace upload and enterprise backend services require their own authorized service contracts. Their unverified availability is not proof of missing local Apexo functionality.
- No Windows, Linux interactive UI, cross-process dashboard or external-service operation was exercised. These remain acceptance boundaries; they are not newly proven missing features.
