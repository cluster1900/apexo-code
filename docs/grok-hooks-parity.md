# Grok host hooks compatibility

The Grok Build runtime profile loads host hook configuration in addition to installed plugin bundles. The Apexo profile continues to load installed bundles but does not execute Grok host hooks. The read-only `GET /hooks` endpoint lists source paths, event names, handler types, matchers, support status, and diagnostics; it excludes command text, HTTP URLs, and environment values.

Host discovery reads additive user requirements, user config and user managed defaults from `$GROK_HOME`, then documented Hook files and explicitly enabled Claude/Cursor imports. All of these sources remain user-disableable. Import flags are host-global, default off, and project files require the existing exact canonical workspace grant. Parent-folder trust is not inherited. See [source layers and trusted imports](native-hook-sources.md) for ordering, duplicate precedence, settings and remaining administrator-policy boundaries.

Supported dispatch boundaries are SessionStart, SessionEnd, UserPromptSubmit, PreToolUse, PostToolUse, PostToolUseFailure, PreCompact, PostCompact, StopFailure, Stop, PermissionDenied, Notification, and StopCancelled. Tool failure observations are deduplicated by message-part identity. Compaction observers currently label their source as unknown because the existing plugin boundary does not provide manual/automatic provenance. SessionStart runs once per session within the instance; SessionEnd runs on instance disposal. Host Stop runs at the actual normal completion boundary in both Apexo execution engines. Installed plugin-bundle Stop observers retain their existing idle behavior. Pre-tool hook denials and permission denials are excluded from execution-failure observations.

Command handlers receive JSON stdin and configured environment variables. Host HTTP handlers require HTTPS, receive JSON POST bodies, validate destination addresses, and reject redirects. Host commands run with the host process's privileges; this feature does not provide the official command sandbox. Hook configurations must therefore be host-trusted. Outputs are bounded, and timed-out command trees are terminated. Ordinary host-handler crashes/timeouts fail open; exit 2 blocks gate events. Installed bundle hooks retain their existing stricter failure behavior.

PreToolUse deny stops execution. Host updatedInput replaces the argument object before built-in validation and permission checks. MCP resource arguments are parsed after hooks; generic MCP rewrites require a schema validator. Ask forces a fresh permission prompt even after automatic or cached allow decisions, and another concurrent always-approval cannot satisfy it. Host denials remain effective. Allow and defer do not raise host permission privileges. Plugin-bundle argument rewriting remains rejected because this extension is scoped to host hook configuration.

Simple tool matchers are exact names or `|` lists; complex patterns are regexes. Official external aliases such as Read and Bash match their Grok and corresponding Apexo names. Invalid regexes match nothing. PostToolUse supports bounded updatedToolOutput and additionalContext.

## Durable Stop continuation

Apexo owns the gate, command/HTTP dispatch, persistence, and provider continuation. The gate claims each real assistant completion once in `session_hook_stop`, keyed by engine and completion ID and validated against the owning Session. Interrupted claims are not automatically replayed. Reasons are bounded to 64 KiB. A blocking reason or additional context requests more work; `continue:false` takes precedence and allows the current work to stop. A single admitted user turn permits at most eight hook-driven continuations, matching the pinned reference gate. Cancellation, errors, exhausted turn budgets, and child roles do not invoke the main Stop gate.

V1 supplies the persisted reason as system context during its next actual provider turn and acknowledges it after processing. V2 supplies a Session-owned SystemContext source and acknowledges only the exact row whose reason is present in the durable context-epoch snapshot. An unavailable replacement cannot silently consume the note. The native runner carries an explicit current-drain token; a pending row cannot restart model execution after a crash or leak into a newly promoted user input. Force-stop does not declare an active Goal achieved; exiting its runner invokes the existing Goal finalizer.

Neither engine creates a user admission for hook continuation. V2 records context updates as durable `system` messages. Its existing provider adapters may lower chronological system messages to user-role wire entries; this established transport representation is distinct from user admission and does not change the durable source provenance. Official Stop-specific payload names `stopHookActive` and `lastAssistantMessage` are emitted alongside the compatibility snake-case aliases.

### HTTPS and network-policy checkpoint

Host HTTP dispatch uses Apexo-owned standard HTTPS transport. Private IPv4 ranges, link-local addresses, unspecified addresses, carrier-grade NAT, IPv6 local ranges, and mapped IPv4 equivalents are rejected; loopback remains permitted. DNS names must resolve successfully and every returned address must pass validation. Redirects are not followed. The overall dispatch deadline and one-million-byte response limit remain enforced.

Host-global GROK_EXTRA_CA_BUNDLE supplies additional certificate roots, falling back to SSL_CERT_FILE only when the primary variable is absent. An explicitly empty primary value disables fallback. Bundles are capped at 1 MiB; unreadable or invalid entries are skipped without disabling TLS verification. Additional roots supplement the runtime's default roots. Runtime trust-store composition and per-dispatch bundle refresh are not claimed identical to the reference's cached Rust roots.

The installed 1.0.52 comparator allows cleartext loopback HTTP, while the pinned source requires HTTPS. Apexo follows the pinned source. The installed runtime refuses private literal URLs during loading; Apexo validates at dispatch after runtime environment expansion. These are recorded comparison differences. DNS rebinding resistance is not claimed by either the reference validation or this implementation.

Existing host HTTP gate, observer, Stop-context, and environment tests now use trusted local TLS and retain their original behavioral assertions. Focused coverage passed 21 tests / 107 assertions; package typecheck and CLI five-scenario checks passed. Stronger CLI diagnostic checks and all 18 isolated installed comparison scenarios passed. The refreshed production Desktop artifact passed all five scenarios. The expanded related suite passed 107 tests / 256 assertions across eight files. See BUG-20261014-107.

### Duplicate host-hook resolution

Supported host sources now resolve duplicates using canonical event, raw command, raw URL, and configured matcher before environment expansion. Global config precedes hook files, and the first equal-authority copy wins. Timeout and environment differences do not create a separate hook under the pinned source contract. Distinct raw expressions remain distinct even if expansion produces the same string. Exact project trust still gates project sources. Installed plugin bundles retain their separate append behavior.

Filtering preserves the original winning handler name in both sanitized inspection and runtime GROK_HOOK_NAME, rather than renumbering surviving handlers. Internal identity metadata is nonenumerable and is not user-configurable. Unsupported or malformed handlers do not reserve the identity of a valid copy.

The installed 1.0.52 control comparison deduplicates copies with identical settings but retains copies whose environment/timeout differ. Apexo follows the pinned raw-content rule; that version difference is explicit. Source CLI passed four scenarios, related tests passed 26 tests / 135 assertions, and package typecheck passed. The installed comparator passed 20 scenarios; the refreshed production Desktop artifact passed all four scenarios. See BUG-20261014-108.

## Session configuration snapshots (runtime checkpoint)

Host configuration is now captured through an Apexo-owned process-global Session snapshot service at actual execution entry. The Location bridge validates the persisted Session placement and loads the existing host trust/configuration rules. Existing Sessions keep their immutable registry when files change; a new Session sees the changed configuration. Resolved handler identity is preserved. Permission, cancellation, and Stop dispatch read the captured registry and never silently rediscover configuration.

The compatibility plugin adapter defers host SessionStart/UserPromptSubmit until execution. Ordinary installed-plugin admission callbacks retain their existing timing. Host prompt dispatch uses the actual durable user message and caches its outcome, so repeated execution of the same prompt neither reruns a successful hook nor bypasses a denied hook. It does not create an input or rewrite the durable user message. Snapshot and adapter cleanup is scoped to Location lifetime and Session deletion; deletion waits for current native ownership cleanup before removing the Session and invalidating its snapshot.

Snapshot inspection and explicit reload are exposed under both compatibility and native Session routes. GET is passive. Reload before capture returns 409; a valid reload is serialized through the Session control lane at the next safe provider boundary without a new prompt or model request. Existing Sessions retain their registry until explicit reload, which rechecks source trust. Reload does not repeat SessionStart or erase exact-message hook receipts, including an older denial after later turns.

Latest backend acceptance passed nine scenarios on CLI and the rebuilt production Desktop backend. The isolated installed comparator passed 22 checks, including retained existing-Session configuration and fresh new-Session discovery. Installed mid-session reload was not directly exercised; its comparison is supported by the pinned command-loop source. Focused Runner/snapshot/adapter tests passed 35 tests/105 assertions.
