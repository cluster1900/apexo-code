# Native Workflow Rhai Reasoning Effort

This slice is integrated and has scoped CLI, rebuilt Desktop, and installed-reference acceptance. All 21 repository typecheck tasks passed. The whole-unit gate for this batch failed in native MCP reload and remains under [investigation](testing/test-stability/mcp-native-reload-full-suite.md); earlier complete Workflow checkpoints predate this addition.

Rhai `agent` options and each `parallel` entry accept an optional case-insensitive `effort`: `none`, `minimal`, `low`, `medium`, `high`, `xhigh`, or `max`. Omitted effort keeps existing model and variant behavior. This adds no public HTTP schema, declarative stage field, or provider bridge.

Each call selects its explicit provider-qualified model or inherits its parent's native model. An omitted parent selection follows the ordinary native Location catalog's supported default/fallback order. Existing native variant payloads are the capability declaration; names such as `high` alone imply nothing. The native API mapping reads Responses `reasoning.effort`, chat-completions `reasoning_effort`, and Anthropic `output_config.effort`. It does not translate legacy AI SDK provider-option objects or invent variants from external model catalog labels.

An already-selected matching variant is retained. Otherwise exactly one existing variant must express the requested effort while preserving all effective non-effort body fields and headers. Unknown efforts, unavailable mappings, ambiguous matches, missing models/variants, and conflicting custom settings fail before child creation or model work. The current variant/body merge deliberately matches `SessionRunnerModel.withVariant`'s shallow overlay semantics; nested reasoning/output configuration fields are compared after removing only the effort property. A custom variant's additional fields or headers are never silently discarded.

Before child mutation admission, `SessionRunnerModel.resolve` performs the canonical native resolution, including credential metadata. The resulting native route's HTTP body overlay must still contain the requested effort. The resolver does not privately merge credentials or use V1 provider orchestration. This check validates resolution-time effort; existing native live catalog/credential semantics are otherwise unchanged, and this slice does not freeze every future provider configuration value.

The final canonical model/variant is saved on the native child. An attached child's saved reference is reused on resume; the mapper does not silently choose a replacement variant. A changed saved variant that no longer resolves the requested effort fails. The Rhai call/task hashes already include effort, so existing replay fencing remains authoritative. Parent agent, permissions, read-only tool filtering, Session ownership, cancellation, agent budgets, and usage accounting remain native and unchanged.

## Reference boundary

The effort vocabulary is defined in `xai-grok-sampling-types/src/types.rs`.

On 2026-10-15, isolated installed Grok 1.0.52 comparison passed six cases with five child requests (16 total provider requests in the final shared-checkout comparison, including auxiliary work): `high` reached the wire; `LOW` became `low`; omitted effort inherited `medium`; `max` reached the wire despite a catalog advertising only low/medium/high; unknown `ultra` failed without a child request; and `high` on a model without advertised support was silently omitted. Apexo deliberately rejects absent or conflicting native mappings instead of reproducing the last two capability inconsistencies. This is a scoped behavioral reference, not a claim of identical validation or external-provider acceptance.

The reproducible command is `bun script/grok-workflow-effort-official.mjs` (`GROK_BIN` can select the installed executable) from `packages/apexo`. It isolates HOME, Grok and XDG directories, creates a private reference profile and local provider, captures catalog metadata separately from actual child wire requests, and reaps its owned process. The installed executable is not used by Apexo product code.
