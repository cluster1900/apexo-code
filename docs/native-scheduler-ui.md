# Native Scheduler management and loop command

This slice adds native schedule intent management to the existing Task/Process panel in App, mini and fullscreen terminals. Schedule rows have a distinct source and identity. Active intent does not count as a running Task. Detail displays the interval, durable option, expiry, next deadline, blocked reason, and latest occurrence/Task identity. An admitted child remains independently manageable as a Task.

Pause and Delete affect future occurrences. Resume revalidates the existing task permission and schedules future ticks; it does not replay an interrupted occurrence or immediately run the model. Both durability values can be retained after a same-Session restart until expiry; current native recovery is paused/restart-required with explicit Resume. The UI does not equate the durable option with generic persistence.

Each source has independent list failure feedback. Native failures do not select compatibility routes. Controls use the five canonical native endpoints and send no body for Pause, Resume or Delete. Native and compatibility adapters keep their existing selection rules. The App translates new management/error copy for English, Simplified Chinese and Traditional Chinese; terminal copy follows its existing English convention. See [the localization review](native-scheduler-ui-localization.md).

## Loop admission

Core command discovery publishes one authoritative `/loop` template. A handwritten browser-safe SDK helper reads `/api/command`, validates supported command metadata and substitutes literal arguments once. App and the common native terminal transport use that helper before ordinary durable prompt admission. There is no privileged schedule-create endpoint, second executor or legacy provider bridge. Missing cadence is left to the ordinary command/model interaction; the host does not invent a period. File attachments, admission IDs and delivery options retain their normal behavior.

The SDK helper rejects unsupported subtask, agent and model metadata. Dollar sequences and multiline arguments remain literal after one substitution. Generic native custom-command execution remains outside this slice. Mini's admission guard permits only the newly supported `loop` command while retaining other unsupported-command and user-shell rejection.

Installed Grok Build 1.0.52 was compared in an isolated local-provider profile on 2026-10-15. Empty `/loop` produces usage/cadence guidance; populated `/loop` expands a prompt asking the model for `scheduler_create`, immediate first fire and a self-contained child prompt. The host does not create a schedule when the model only returns text. `bun script/grok-loop-official.mjs` preserves this reproducible comparison. The fresh comparison completed both empty and populated cases with four total provider requests, including auxiliary requests. Its evidence is reference behavior, not a test of Apexo. Apexo's explicit restart Resume, native same-child bounded continuation, accepted-Stop ownership and expanded transcript presentation retain the separately documented native boundaries.

## Ownership and verification

The App's manager controller belongs to the Session page, outside the composer branch replaced by permission UI. Deny preserves the paused intent and visible action feedback; Allow once completes the pending action without a new provider turn. Both composer variants receive the same optional typed controller, with local fallback for standalone use. Hidden but owned tabs are distinct from disposal. Existing Session/SDK effect cleanup aborts requests and timers. Client abort and backend control joining are verified and reported separately; a network response ordering observation alone does not prove either.

Private focused verification currently includes 31 App tests/367 assertions, 40 terminal adapter tests/158 assertions, five SDK helper tests/13 assertions, and App/Apexo/TUI package typechecks. The SDK helper is exercised through its exported package path and the private frozen-lock install. Generated outputs are validation-only and are excluded from the UI handoff.

Earlier mini 80×24 and fullscreen 120×40 management checks also passed; compatibility mini 80×24 and fullscreen 120×40 real Task output/cancellation checks passed. The actual rebuilt Desktop window also passed seven locale checks / seven calls and two permission checks / five setup calls.
