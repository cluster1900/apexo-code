# BUG-20261015-190: Compiled CLI split chunks collide

- **Status:** Corrected; standalone build and compiled interaction verification passed.
- **Scope:** The macOS arm64 standalone CLI build with pinned Bun 1.3.14 after native-local terminal integration. Source terminal checks and the Electron build pass independently.
- **Observed:** The CLI compiler exits one with `Multiple files share the same output path`, naming one generated JavaScript chunk and `packages/sdk/js/src/process.ts`. No compiled CLI smoke test runs.
- **Expected:** The standalone executable embeds its split modules with distinct paths and starts both native and compatibility terminal workers.
- **Reproduction:** From `packages/apexo`, run `bun script/build.ts --single --skip-install --skip-embed-web-ui` with the repository's pinned Bun. An existing local model-catalog snapshot may be supplied through `MODELS_DEV_API_JSON`.
- **Cause:** The actual failure is a collision under Bun's default hash-only chunk naming. The exact reason these chunks receive the same name has not yet been isolated. Later [Bun release notes](https://bun.sh/blog/release-notes/bun-v1.4.1) describe a related empty-chunk collision, but that upstream report alone does not prove the cause in this graph.
- **Correction:** Seven client-only runtime consumers now import the SDK client entrypoint instead of the barrel that also exports server-launch helpers. This removes unused server/process imports from those lazy entry graphs while retaining the public SDK server exports. Expanding the chunk naming template did not resolve the collision and was reverted. Narrowing only the newly added import was also insufficient; the existing client-only consumers needed the same boundary. The compiler, splitting and entrypoint paths are unchanged.
- **Verification:** Original and naming-only builds exited one. The complete client-entry correction built the macOS arm64 executable, passed ad-hoc signing and its actual version smoke test. All eleven compiled terminal/rejection commands passed after correcting the separate inspection-database fixture issue [BUG193](../test-fixtures/native-local-compiled-database.md). This is one observed build episode, not a recurring constraint.
