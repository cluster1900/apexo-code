# BUG-20261015-097: Compatibility Plan entry bypassed configured ask

- **Scope:** Compatibility `plan_enter` / Grok-profile `enter_plan_mode` tool, real CLI and packaged Desktop backend.
- **Status:** Integrated; real CLI and rebuilt Desktop backend acceptance verified.
- **Observed:** With `permission.plan_enter = "ask"`, the real model tool call switched to the Plan agent and wrote the existing synthetic Plan input without creating a pending permission request. `allow` behaved the same. `deny` hid the tool.
- **Expected:** An ask rule must wait for the user's permission response before changing the agent or writing the transition input. Rejection must leave the original agent/input unchanged.
- **Reproduction:** Run a real compatibility Session using the local provider fixture; configure `plan_enter` as ask, emit `enter_plan_mode`, poll the actual permission endpoint, and inspect persisted user messages. The pre-fix run had zero requests and one synthetic Plan-agent input.
- **Root cause:** The built-in tool wrapper delegates authorization to each tool. `PlanEnterTool.execute` never called `ctx.ask`; visibility filtering only removed denied tools, so it could not enforce ask.
- **Fix:** Call `ctx.ask` with canonical `plan_enter` and resource `*` before reading Session/model state or persisting the existing transition. This preserves default allow behavior and the compatibility synthetic-message lifecycle. Native Plan migration remains a separate feature.
- **Verification:** From `packages/apexo`, `bun script/grok-plan-permission.mjs cli` passed 6 checks across allow, ask-approve, ask-reject and deny, with 10 local-provider requests. Both ask cases observed a real pending request and no Plan input before reply. Approved entry continued with the Plan agent; rejection and deny produced no Plan input. `bun typecheck` passed in the coherent private draft. After hash-verified shared integration and Desktop rebuild, both real CLI and packaged Desktop backend repeated six checks / ten local-provider requests with clean process exit. The shared Apexo package typecheck also passed.
- **Reference boundary:** Installed Grok 1.0.52 enters without a permission question by default. Its configured ask rule prompts and respects rejection; hard deny blocks execution. Exit additionally requires an explicit approval response. Official default/ask/deny comparison passed 5/4/1 checks with 14/9/10 local-provider requests. Default allow is not evidence of a user's explicit approval.
- No recurrence promotion: these scenarios demonstrate one implementation defect.
