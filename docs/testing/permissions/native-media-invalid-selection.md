# BUG-20261015-141: Invalid explicit media configuration exposed provider defaults

- **Scope:** The new native media-options draft; no claim that the S3 feature was already shipped.
- **Observed:** A real native Session had a valid lower-priority provider configuration and a higher-priority document selecting S3 with required fields missing. The media tool issued two provider API requests instead of zero. The focused regression failed with `Expected: 0, Received: 2` (one failure, three assertions).
- **Expected:** Invalid explicit output selection fails before provider work or secret resolution; it must not silently become ordinary provider output.
- **Root cause:** Native Config ignored a document when full Info decoding failed. The new media leaf initially treated absence as provider defaults without preserving evidence that the higher-priority document explicitly selected media output.
- **Fix:** A rejected parsed document that explicitly owns `media` retains only an internal `Config.Document.mediaInvalid` marker and empty Info. No permissions, providers or other fields are salvaged. Media selects the highest-priority valid media value or invalid marker. The marker fails before resolving environment values; a higher valid explicit media value can replace it. Public Info retains its exact schema.
- **Related entrypoints:** ConfigV1 forwards the same media leaf; invalid Config API payloads are rejected before writing. Native plugin bundles construct only supported command/agent/MCP/LSP fields and validate their configuration. Native Config also strictly decodes migrated bundle Info, so a malformed injected candidate cannot silently produce provider defaults. No new plugin media capability is introduced.
- **Reproduction:** Run the malformed higher-priority native media case in `test/e2e/v2-media-options.e2e.test.ts` before the carrier change.
- **Verification:** After the carrier change, five actual HTTP cases passed with 19 assertions: native and V1 invalid selections, simultaneous invalid media/other fields, valid higher selection replacing invalid lower selection, and rejected Config API mutation with unchanged file. Blocked media cases issue zero provider requests. The final combined gate passed 32 tests / 231 assertions, including environment-override non-bypass and internal Document roundtrip. Core and Apexo package typechecks passed; the final native CLI options fixture passed five checks / eight provider calls.
- **Occurrences:** One confirmed draft integration episode. Passing retries are not additional occurrences.

Shared integration verification: all 21 workspace typechecks passed, and the combined native Shell/media/Plan suite passed 68 tests / 623 assertions. Shared CLI and freshly rebuilt Desktop passed Shell nine checks / 26 calls each and media-options five checks / eight calls each. These are scoped gates; the earlier full-unit checkpoint is not claimed for the later integration.
