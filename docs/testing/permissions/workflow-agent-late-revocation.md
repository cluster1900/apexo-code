# BUG-20261015-348: Selected Workflow child ran after late delegation revocation

- **Scope:** Native Workflow `agent_type` admission and owned child execution.
- **Observed:** Holding the real child `session.created` notification, changing the parent's native `task` permission for the selected helper to `deny`, then releasing the notification still allowed one child provider call in the initial agent-selection implementation.
- **Expected:** Revocation after initial model/permission admission but before child execution prevents the child drain from invoking the provider. The Workflow records a failed result without transferring ownership elsewhere.
- **Reproduction:** Run `test/workflow/agent-admission.test.ts` without the runtime's post-preparation and pre-drain `WorkflowAgent.verify` calls. The test starts a real parent Session whose provider invokes a selected-agent Workflow, holds the child's Created notification with an EventV2 listener, revokes native delegation policy through AgentV2, releases the notification and joins the parent drain.
- **Root cause:** Initial admission checked policy before journal writes, sandbox preparation and Created notification. The later native child drain used the saved selection without checking whether delegation had been revoked during those asynchronous boundaries.
- **Fix:** Reuse native Agent availability, parent Agent identity and PermissionV2 checks after sandbox preparation and immediately before each owned child drain. Add the fresh parent authority to the original immutable ceiling supplied by WorkflowRole. Workflow still owns the same managed child Session and uses the existing Session coordinator, provider call and permission evaluator.
- **Failure-before evidence:** On pinned Bun 1.3.14, the focused test failed `expected []` versus `["model"]`, proving one actual child provider request after revocation. This is one independently reproduced defect, not multiple occurrences.
- **Verification-after:** `bun test test/workflow test/e2e/v2-workflow-agent.e2e.test.ts test/e2e/v2-workflow-model.e2e.test.ts --timeout 30000` from `packages/apexo` passes 40 tests, zero failures and 273 assertions. The held-boundary regression verifies zero child provider calls, only two parent calls, one failed Workflow and its permission-changed message. Pinned Apexo `bun typecheck` passes. After shared integration, the combined Task/Hook/Workflow gate passes 76 tests / 675 assertions across 24 files, both package typechecks pass, and source CLI passes four checks / two child provider calls. The freshly rebuilt Desktop backend passes the same four checks / two calls, and all 21 workspace typecheck tasks pass (19 valid cache hits). The separate installed comparison passes three cases; it does not verify this native revocation repair.
