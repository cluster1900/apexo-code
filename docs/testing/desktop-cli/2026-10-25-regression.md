## Goal evidence

A minimal request through the real native Antigravity adapter reproduced HTTP 400 when the history ended in an assistant turn. The upstream diagnostic was `Requests ending with a model turn are not supported.` Adding the corrective user turn succeeded with the requested response marker. This identifies a request-shape problem rather than an account failure.

A separate real Desktop Goal deliberately returned `WRONG_ON_PURPOSE` on its first worker attempt. Independent review requested correction, and the next worker response was exactly `GOAL_CORRECTED_OK`, with no HTTP 400. The server transcript contains two distinct successful assistant turns and no extra durable corrective user message. Independent evaluation confirmed the transition. During the additional adversarial verification, a verifier requested an out-of-scope recursive search of user/system directories; it was denied and the Goal paused with review failure at 384730 tokens. That final stage is not counted as completed. The separate 485621-token lifecycle run below supplies full 3/3 completion evidence.

The full deterministic Goal integration test executes a rejected worker result followed by another worker turn, independent evaluation and completion, both with unlimited steps and with a one-step worker. The limited case initially failed because the maximum-step reminder appended an assistant turn after correction. After making that reminder a user turn, both cases pass (18 assertions). The corrective request ends in a user turn and the durable transcript still contains only the original user message. A real Gemini CLI with `steps: 1` also exits 0 in 7.13 seconds, returns `CLI_LAST_STEP_OK` and acknowledges the step limit. The equivalent Core native reminder initially still reproduced HTTP 400 in 6.52 seconds; after changing its role too, real Gemini returns `NATIVE_LAST_STEP_OK` in 6.87 seconds. Native execution retains its intended step-limit outcome: exit 1, `reason: turn_limit`, `usageIncomplete: false`, and no provider error. Five CLI subprocess tests now pass with 16 assertions, covering both protocols and native final-step request shape.

A real Desktop 200000-token Goal produced the correct marker, passed evaluation and reached one independent verifier, then correctly stopped because the remaining 3354 tokens could not fit the estimated 20120-token context. That budget-limited run is not counted as completed. A subsequent Goal with a 600000-token budget reaches **Verified complete**, with all 3/3 independent verifier reports confirming requirements and 485621 reported tokens. Its final response is exactly `GOAL_RECOVERY_OK`.

## Production session benchmark

Five samples per production bundle use the same retained fixture transcript and viewport. The pre-change medians were 187.61 ms to open the session and 169.49 ms to open Context. An intermediate fixed bundle measured 187.02/160.14 ms. The final bundle was also measured during full-suite load (383.81/344.34 ms); that unmatched-load result is retained but is not sufficient to attribute a performance regression. With both bundles measured under the same remaining HttpApi workload, medians were 354.89/275.17 ms before and 334.28/301.34 ms after (session −5.8%, Context +9.5%). After all test workers and generators finished, the final idle comparison measured 213.14/185.53 ms before and 205.44/191.67 ms after (session −3.6%, Context +3.3%, a 6.14 ms Context delta). Five-sample results are descriptive rather than a formal statistical performance guarantee.

## Evidence limits and intermediate failures

- The first Context patch covered legacy helpers but missed the active server-session cache. Its real Desktop run still showed 7 messages/2 users versus 6/1 on the server. The active path was then fixed, directly tested and rerun successfully in a fresh window.
- After the seven fixes passed acceptance, #147–#153 were closed at the user's request with links to this report. Final-head gate follow-up found two Linux Memory timeouts (#159), a local batch watchdog hang (#160), and repeated PR Agent job timeouts (#161). The [gate follow-up](../test-stability/2026-10-25-acceptance-gates.md) preserves evidence and distinguishes diagnostic/configuration changes from verified fixes. Exact-head final outcomes remain on PR #155.
- At `fefd250`, the final independent local unit run passed all 6 tasks, 17 batches and 501 files in 9m10.629s; all 17 PR checks passed and PR #155 was merged as `c5e4227`. Post-merge Linux CI reproduced #159 with diagnostic proof that automatic work had already started and was still running. Its follow-up separates the original five-second admission guard from the existing bounded Memory completion wait, and adds an actual six-second HTTP response control. Details and final follow-up verification are linked from the same bug record; none of the seven product fixes changed in this follow-up.
- A later complete gate failed in three unrelated cases: OAuth readiness (`load`), task metadata readiness and native Plan shell completion. Their exact evidence, a separately reproduced OAuth expiry assumption, its fixture correction and unchanged successful controls are retained in the [gate follow-up](../test-stability/2026-10-25-acceptance-gates.md). A subsequent unit-only run passed those batches but returned one unexplained HTTP 400 in the legacy 510-message limit test; its exact batch replay passed 185 tests. It is tracked as [#158](https://github.com/cluster1900/apexo-code/issues/158), with error-body diagnostics retained. These root causes remain unresolved; a passing rerun is not labeled a fix. OAuth expiry then passed 10 repeated runs with 110 assertions.
- The in-progress full gates were deliberately interrupted after discovering the native final-step HTTP 400; that partial run is not counted as a final pass. Required gates were restarted after the Core fix.
- The first added native subprocess fixture failed with `Model unavailable`, so it did not exercise variant validation. The corrected fixture writes native configuration and explicitly passes its isolated directory (the subprocess inherits a different `PWD`); only its variant-specific error and zero-hit result count as acceptance. An initial test edit also hit an automatic-semicolon-insertion loading error before test execution; it was corrected before the passing runs.
- HTTP/queue integration fixtures supplement live acceptance; they are not substituted for real model execution.
