# BUG-20261015-053: Private validation overlay changed dependency identities and mixed source revisions

- **Scope:** Off-tree Hook preference and native command sandbox validation infrastructure; not an application defect.
- **Observed:** Early private typechecking mixed live and private Core declarations. Later App typechecking could not resolve `@apexo/client/promise`, with downstream unknown/implicit-any errors, and TUI typechecking reported missing Workflow fields.
- **Expected:** A private validation workspace preserves the actual workspace-versus-vendored package identity and checks a coherent source snapshot.
- **Root cause:** The overlay initially copied too few workspace packages. Its link copier then treated every `@apexo` dependency as a workspace package, incorrectly replacing App's vendored Client with the distinct workspace Client. Unowned Schema files also remained older than copied Workflow consumers.
- **Fix:** Copy the complete workspace, remap only dependencies whose resolved paths are actual workspace packages, preserve vendored targets, and refresh unowned sources at a coordinated stable checkpoint before private Client and SDK generation. Generated output remains excluded from integration.
- **Reproduction:** Typecheck App with its vendored Client remapped to workspace Client, or typecheck current TUI against the older Workflow schema.
- **Verification:** Private App and TUI package typechecks passed after correcting the overlay. Final Core, Server and Apexo package typechecks also passed. The private production App build completed successfully.
- **Additional setup correction:** An initial private build command used `bun build` instead of `bun run build` and exited before compilation with missing entrypoints. The package build script is the intended command.
- **Second independent occurrence:** The command sandbox overlay copied current Workflow/Server consumers while retaining older Core OAuth and Workflow engine sources. Some package dependencies also resolved to the live workspace, producing duplicate `APEXO_VERSION` declarations. The first combined check reported missing OAuth/effort members and mixed declaration identities. Refreshing the complete coherent live source baseline, preserving only explicitly owned overlays, and remapping actual workspace targets resolved those fixture errors. Current Task guard changes were composed as narrow hunks rather than copying stale whole files over newer Hook handling. Private Server and Apexo package typechecks then passed.
- **Third independent occurrence:** The sandbox UI validation overlay refreshed current App/TUI/Apexo sources but retained an older TUI package manifest. Actual mini startup failed to resolve the already integrated `@apexo/tui/util/session-tasks` export. The captured terminal showed that exact module-resolution failure; component tests using absolute imports had not exercised the package export boundary. Refreshing the manifest from the same live checkpoint, preserving its existing exports and adding the new sandbox component export, repaired startup. This was an overlay inconsistency, not a Task product defect.
- **Third-occurrence verification:** In `packages/apexo`, `bun script/grok-sandbox-terminal-route.mjs --new` and `bun script/grok-sandbox-terminal-route.mjs --fullscreen --new` each pass three real CLI route checks with zero provider calls. App, TUI and Apexo package typechecks pass for the coherent overlay. The fullscreen Home registration defect is separately recorded as [BUG093](../ui/sandbox-home-command.md).
- **Fourth independent occurrence:** A separate managed-resume validation overlay combined a frozen managed-child snapshot and newer staged ownership sources but retained an older unowned mixed-server `httpapi/server.ts`. Apexo typechecking reported a missing service requirement because that stale file lacked the already integrated `SessionCommandSandbox` import and public group export. Refreshing exactly that unowned file from the live checkpoint resolved the error. The service export was present in production; this was not another missing-service fixture construction occurrence under BUG134.
- **Fourth-occurrence verification:** The owning agent's Apexo package typecheck passed after that exact refresh, and its actual-runtime focused gate passed 39 tests / 272 assertions. These are reported owner verification results, not a duplicate rerun by the sandbox UI agent.
- **Fifth independent occurrence:** The native background Task validation tree refreshed the new managed-resume production boundary but retained old unowned tests. The Created-admission test still supplied public `execution.resume` as a trusted child capability; the live test already captured the actual `CurrentChildren` capability. Another retained the pre-generalization Workflow rejection message. Both old/live diffs were inspected. These stale consumers caused the private failures; they were not silently classified from a passing rerun.
- **Fifth-occurrence correction and verification:** Refresh the complete source/config/document checkpoint while retaining only owned edits: 5,274 files inventoried and 78 changed/missing unowned entries refreshed, including current execution consumers. Audit 552 dependency links and preserve App's vendored Client identity. Regenerate Client/SDK privately. Core, Apexo, App and TUI types passed; actual CLI background acceptance passed eight checks / 32 calls. The coherent combined Task gate passed 32 of 33 tests, including the corrected authority/admission cases; its distinct pre-Task connection reset remains [BUG106](../test-stability/task-background-connection-reset.md), with no transport repair inferred.
- **Sixth independent occurrence:** The completed-child Task message wake overlay refreshed all current source files and manifests, but cloned dependency trees from its earlier operator UI snapshot. The new MCP consumer imported `uri-template`, which was present in the shared frozen-lockfile installation but absent from that older dependency graph. The first focused test command failed during module loading before any test assertion ran. This was an overlay construction failure, not a completed-child execution defect.
- **Sixth-occurrence correction:** Refresh every root and package dependency directory from the same stable shared checkpoint, including `uri-template` and its `pct-encode` dependency. Audit all 5,234 symlinks: no target resolves to shared workspace sources or the earlier private snapshot, and App's Client remains its intentionally vendored package. Verification of the completed-child implementation is recorded separately; dependency repair alone does not establish feature correctness.
- **Sixth-occurrence verification:** A fresh source/manifest audit reports no unowned differences from the coordinated shared checkpoint and no root dependency links resolving to shared workspace packages. Core and Apexo package typechecks pass, the focused Task-message gate passes 12 tests / 174 assertions, and the real source CLI wake matrix passes all three delivery modes. Later shared Hook changes are separately composed during integration; these scoped results do not claim rebuilt Desktop or full aggregate acceptance.
- **Seventh independent occurrence:** The Shell prefix/output snapshot copied coherent files but compared absolute symlink text using canonical `private` temporary paths against links spelled with the temporary alias. This left 112 workspace links targeting the preceding Shell snapshot. The first after-run repeated the prior implementation failures; inspecting the resolved Core package entry proved the stale identity. Resolve each target before testing workspace containment, remap only those targets, and preserve vendored dependencies. An audit of all 4,353 links and actual package entrypoints preceded a fresh negative/positive pair. The corrected focused union passes 25 tests / 247 assertions and source CLI passes two cases; the first private typecheck is superseded.
- **Occurrences:** Seven independently constructed private validation overlays. Multiple corrections or repeated attempts within one construction episode count only once. Promoted to [RULE-20261015-005](../../rules/coherent-private-validation.md).

## Related source-inventory audit correction

A later automatic Dream workspace was cloned from an untracked private predecessor using that predecessor's `git ls-files --others --exclude-standard` inventory. A pre-build prerequisite audit found that it omitted five paths present in the predecessor's canonical shared-source checkpoint, including the tracked `packages/apexo/script/build-node.ts`; the other four were editor/ignore configuration files. No build was attempted before the omission was detected, and the runtime source and package typechecks were unaffected. The copy was repaired from the canonical predecessor manifest with before/copy/after hashes for all omitted paths. Future clones from an untracked private tree must use its canonical checkpoint plus owned-file manifest, not treat its untracked Git inventory as the authoritative source list. This explicitly recorded audit correction does not change the independently verified occurrence count above.
