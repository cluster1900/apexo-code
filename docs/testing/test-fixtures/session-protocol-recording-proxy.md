# BUG-20261015-167: Diagnostic HTTP proxy changed response encoding and did not settle SSE cleanup

- **Scope:** Newly authored mixed-server request recorder; one diagnostic fixture episode with distinct transport and cleanup defects.
- **Observed:** The first fetch-based proxy forwarded `content-encoding` after fetch had decoded the body, causing a client `ZlibError` on native catalog reads. Its default Bun listener also reported the ten-second idle timeout for a live event stream. After these corrections, interaction assertions completed but recording-proxy shutdown still failed to settle; those runs are not complete acceptance passes.
- **Expected:** Observation preserves response bytes and does not alter the terminal's encoding, streaming, or lifecycle contracts. Every owned proxy, upstream request, terminal and backend must terminate.
- **Cause:** The recorder treated a decoded fetch Response as the original encoded wire response, used a finite listener idle timeout for SSE, and did not reliably close all forwarding resources before awaiting shutdown. The separate mechanisms belong to this one recorder-authoring episode, not recurrent product failures.
- **Fix:** Use a byte-preserving `node:http` forwarding server; preserve upstream wire headers with the unmodified stream. Track upstream requests and destroy them when their outgoing response closes or the recorder stops. Explicitly cancel the fixture's SSE reader, bound shutdown, and put backend cleanup in a finally block. No production retry, timeout, or decoding behavior changed.
- **Verification:** `node --check script/grok-plan-ui-fixture.mjs` passed. Actual mixed mini and fullscreen completed prompt/Question interaction and native-only request assertions, then exited 0 with owned cleanup reaped. Original direct attachment timing remains BUG166 and is not called repaired by this recorder.
