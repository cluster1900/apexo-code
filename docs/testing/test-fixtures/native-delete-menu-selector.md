# BUG-20261015-018: Session deletion UI fixture could not select a present menu item

- **Scope:** `packages/apexo/script/grok-native-session-delete-ui.mjs`, browser and actual Desktop acceptance.
- **Observed:** The first browser run failed on `[role="menuitem"]:has-text("Delete")`. Its immediately preceding accessibility snapshot already showed the correct expanded More options menu and the `Delete...` menu item. The failure screenshot showed the same visible menu. The fixture stopped before opening confirmation; this was not an API deletion failure.
- **Expected:** The fixture selects the actual localized deletion action, checks confirmation, verifies Cancel preserves the Session, then confirms deletion exactly once through the native endpoint.
- **Root cause:** The fixture's CSS/text pseudo-selector did not resolve the present menu item in the automation command path. The evidence rules out the proposed wrong-menu or delayed-menu explanation. This record does not claim that text pseudo-selectors fail in every automation context.
- **Fix:** Use the supported semantic role/name command with the exact localized `Delete...` accessible name, including its ellipsis. Use exact localized button names for Cancel and confirmation. Keep the dialog-title, persisted Session, route-navigation, native HTTP 204, request count, and zero-provider assertions intact.
- **Reproduction:** From `packages/apexo`, run `bun script/grok-native-session-delete-ui.mjs cli --locales` against the original fixture. The first menu click fails despite the recorded menu being present.
- **Verification:** The repaired browser command passed seven checks across English, Simplified Chinese and Traditional Chinese. `bun script/grok-native-session-delete-ui.mjs native --locales` then passed the same seven checks in the actual rebuilt Desktop window. Each run observed exactly three native DELETE requests returning 204, no compatibility DELETE requests, and zero provider calls. Both processes exited successfully and were reaped. Native confirmation text and screenshots were retained; the Traditional Chinese dialog was visually inspected.
- **Status:** Verified fixture-only correction; no product implementation, build or generated-code changes were required.
- **Occurrences:** One fixture-authoring failure. Browser/native verification runs are not independent failure occurrences.
