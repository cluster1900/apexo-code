# BUG-20261014-158: Native window fixture selected an unregistered server

- Scope: native macOS Goal, Feedback, and Hooks UI acceptance fixtures.
- Observed: the freshly built Desktop window displayed “This session cannot be found” for the fixture's external native server and valid Session. Instrumented native-server logs showed only the fixture's health/create calls and no Desktop requests. Browser acceptance using a same-origin server had passed.
- Expected: Desktop resolves a registered external server connection and loads its native Session before opening management panels.
- Reproduction: set only `window.api.setDefaultServerUrl` and restore a `/server/<key>/session/<id>` route in a clean Desktop profile whose persisted server list is empty.
- Root cause: selecting a default server key does not register a connection. Desktop initially supplies its sidecar connection, while the external fixture connection must also exist in the persisted Server list. Route resolution failed before protocol detection or HTTP transport ran.
- Fix: the fixtures initialize the isolated profile's Server list through the existing `storeSet` bridge before reloading its saved route. Locale captures also use Desktop's actual persistent language store in addition to the browser warm-start value. The fixture remains attached to the actual native-only Core server. No production or backend code changed.
- Verification: the instrumented failure confirmed zero Desktop traffic. After registering the connection, the native macOS rerun resolved the Session, opened Goal, and completed its passive-read check; Desktop GET requests reached the native server with the correct Session and directory. The subsequent mutation hit a separate native CORS failure, recorded in [BUG-20261014-159](../runtime/native-server-cors.md). After that separate correction, native macOS commands `bun script/grok-native-goal-ui.mjs native`, `bun script/grok-native-feedback-ui.mjs native`, and `bun script/grok-native-hooks-ui.mjs native --locales` from `packages/apexo` passed 7, 12, and 8 checks respectively. Each fresh isolated profile resolved its registered native server. All owned processes were reaped.
