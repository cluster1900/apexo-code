# BUG-20261015-137: Media screenshots retained the preview-button scroll position

- **Scope:** Native media browser/Desktop acceptance fixture; production media source is unchanged.
- **Observed:** Browser playback checks passed, but screenshots appeared black. They captured only the lower portion of the portrait video; the colorful frame was above the clipped conversation viewport. Native-window captures at their larger viewport already showed the frame.
- **Expected:** Verify a decoded, advancing video and reveal its actual frame before capturing evidence.
- **Reproduction:** Run `bun script/grok-native-media-ui.mjs browser --locales` from `packages/apexo` with the original fixture. It scrolls the short Preview video action into view, replaces that action with a 480-pixel player, then captures without revealing the resized player.
- **Root cause:** Scroll anchoring after the height change retained a player rectangle with top -194 and bottom about286. Frame-region hit tests were false before explicit reveal. Waiting for `requestVideoFrameCallback` alone still produced the same cropped image, ruling out missing decoding as the cause of this screenshot symptom.
- **Fix:** Reveal the actual loaded player and wait for frame-region hit visibility before screenshots. Additionally require a presented frame with positive dimensions and an advancing playback clock. During fixture authoring, an intermediate version incorrectly equated callback media time with the element clock; the callback can describe a frame ahead of the clock. The final predicate waits for both rather than pausing early or weakening the clock assertion.
- **Verification:** Final browser acceptance passed 12 checks / ten fixture-provider calls across en/zh/zht, with decoded frame metadata, advancing playback, frame visibility, lazy reads, Blob cleanup, reload and missing-file behavior. All six browser before-reveal observations reproduced the clipped geometry; final screenshots visibly show the colored frame. Actual rebuilt Desktop passed the same final 12 checks / ten calls; final browser and native frame screenshots were inspected. Both processes exited zero and owned resources were reaped. Earlier green time-only runs do not establish screenshot visibility.
- **Occurrences:** One fixture-authoring episode. Repeated locale captures and the intermediate readiness-predicate correction are not independent recurrences. No media decoder or product scrolling defect is claimed.
