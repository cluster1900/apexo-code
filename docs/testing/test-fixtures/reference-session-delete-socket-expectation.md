# BUG-20261014-268: Reference deletion fixture assumed physical provider socket closure

- Scope: Isolated installed Grok Build 1.0.52 deletion comparison, using a private home/workspace and a deterministic local provider. No Apexo product code was changed by this audit.
- Observed: Idle, repeated, and unknown-ID deletion returned success. During an active held provider request, deletion returned success and the ACP prompt settled as cancelled with `cancelTrigger=session_delete`. The fixture then timed out waiting 15 seconds for the provider response object's close event.
- Expected: The comparison must distinguish observable Session cancellation from an unestablished physical HTTP socket-close guarantee.
- Root cause: The fixture asserted a stronger transport property than the inspected reference contract or prior evidence established. Whether the response-close observation reflects transport behavior or the fixture's HTTP instrumentation remains unresolved. It is not evidence of a verified Grok transport defect.
- Correction: Assert successful deletion, ACP cancellation settlement, no additional provider work, failed loading of the deleted Session, and persistence after process restart. Record socket-close observation separately without using it as a cancellation proxy. No transport fix is claimed.
- Reproduction: Start an isolated installed Grok ACP process against a local provider; create a Session; hold its chat response before sending headers; call the Session delete extension; observe the prompt's cancellation result; separately wait for the provider response close event. The initial comparison failed only at that final socket assertion and cleaned up its owned process and server.
- Verification: The corrected isolated comparison passed four checks with four provider requests and completed teardown. It verified idle/repeated/missing deletion success, deleted load rejection, active prompt cancellation without retry, and deleted load rejection after process restart. `providerSocketClosedAtDelete` was false. Physical transport closure remains unverified; a passing rerun does not establish it.
- Occurrences: One fixture expectation failure. No recurring rule is warranted.
