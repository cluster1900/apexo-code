# BUG-20261014-274: Native project bootstrap called absent project endpoints

- Scope: Production App and macOS Desktop connected to the native-only server.
- Observed: Goal feature checks passed, but screenshots showed `Failed to reload workspace / UnexpectedStatus`. Request traces from both browser and native-window fixtures showed three 404 attempts each for `/api/project/current` and `/api/project`.
- Expected: Native project bootstrap must return real persisted project metadata and resolve the current project's identity, without requiring compatibility routes or substituting fake empty success.
- Root cause: The App's archived client contract still includes both native project reads. `bootstrapDirectory` invokes `project.current`; its collected slow-request error emits the reload toast and leaves directory status partial. Global bootstrap also calls `project.list`, but its existing error collection does not show a toast. Native Protocol/Server exposed ProjectCopy routes but no native project list/current routes. The optional model-default 404 is a separate handled condition.
- Fix: Add a global Core ProjectCatalog service backed by ProjectTable, a current-project schema, and native list/current Protocol/Server handlers. List returns validated persisted metadata or a sanitized typed 503 failure. Current returns the request Location's authoritative project identity. The handler captures the global catalog during construction. The App and its error behavior remain unchanged.
- Reproduction: Connect the production App to native-only routes, open a Session directory, and inspect bootstrap traffic and error toasts. A missing current route retries three times before the toast. Repeated screenshots and browser/native observations are one integration bug, not independent recurrences.
- Verification: Core and Apexo package typechecks passed. From `packages/apexo`, `bun test test/project/native-catalog.test.ts test/e2e/v2-project.e2e.test.ts` passed three tests and 28 assertions. They cover persisted optional metadata, genuine empty storage, explicit invalid-storage failure, native plain/Git project identity matching Session creation, HTTP list/current success, and zero model work. The dedicated real CLI script `bun script/grok-native-project-catalog.mjs cli` also passed four checks with zero provider calls, including identity/catalog persistence after process restart. Production browser and actual native-window runs each passed the Goal regression's 15 checks and MCP manager regression's 12 checks; all required successful project reads and no UnexpectedStatus reload toast. Final native screenshots were visually inspected. The final rebuilt Electron Desktop backend also passed the dedicated four checks with zero provider calls.
- Related implementation failure: nullable optional fields initially caused 503; that distinct adapter mistake is recorded as a second occurrence of [BUG-20261014-170](../runtime/plugin-embedded-skill-optional-description.md).
