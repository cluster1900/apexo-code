# BUG-20261113-F04-006: Terminal form hydration omitted native Task descendants

- Scope: Native mini/fullscreen TUI, App/Desktop form hydration, SDK watcher, and the pending-list HTTP endpoint.
- Observed: Mini queried only the attached Session because native Tasks do not populate compatibility subagent tabs. Fullscreen queried only the root and its immediate children. An interactive child or grandchild could therefore wait on a form that the operator could not see. App's recursive traversal still depended on frontend metadata being present.
- Expected: The viewed Session can display and answer any live form in its own subtree, including nested Tasks in other Locations. A sibling or unrelated Session must not expose or answer the request.
- Reproduction: Configure `task.maxDepth: 2`, have an interactive root launch a worker, optionally have that worker launch another worker, and invoke the real MCP `collect` tool in the leaf. Attach mini/fullscreen to the root without opening the child.
- Root cause: Frontend-only discovery used compatibility tabs or shallow/partially hydrated Session metadata rather than the actual native Session ancestry.
- Fix: The existing pending-list endpoint accepts optional `includeDescendants=true`. It reads only cached live Location scopes, checks pending requests against authoritative Session ancestry, and orders the matching requests. Default listing and all replies remain Session-local. All four UI surfaces use the shared watcher against the viewed root, without enumerating child metadata. The watcher preserves descendant request identity and transient-failure state by queried root and fences scope changes.
- Verification: Real mini/fullscreen PTYs and production browser/rebuilt Desktop windows cover direct and nested Task forms. API acceptance also covers a worktree child, canonical Promise/Effect clients, unrelated-Session exclusion and owner-only replies. The native/mixed HTTP end-to-end test exercises the production handler through the generated Effect client and verifies the completed tool's typed result. Exact final gate results are in [the implementation checkpoint](../../development/f04-implementation.md).
- Occurrences: One audit with two affected terminal discovery paths; this does not establish independent historical recurrence.
