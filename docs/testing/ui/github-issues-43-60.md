# BUG-20261020-001: GitHub Issues #43–#66 Root Cause, Fix, and Verification Record

- **Bug ID**: `BUG-20261020-001`
- **Affected Scope**:
  - `packages/apexo` (CLI argument validation, unknown commands, session ID validation, stderr logger gate, skill command parts, title generation, stealth model filtering, `--mini` keymap teardown order, `mcp debug` exit code, Bash 3.2 & Zsh shell completion scripts, `session list --format json` empty array output, `--help` stdout stream)
  - `packages/tui` (attach server error handling, branding, `/usage` pluralization and wrapping, sidebar context percentage, `/debug` local date)
  - `packages/core` (`PluginStore` source path validation, package directory cleanup on uninstall, marketplace branding normalization, `sessionRow` archive timestamp persistence)
  - `packages/app` (Desktop app menu width, Plugins UI and confirmation dialogs, Provider connect validation and navigation, session export native dialog flow, session title formatting, context limit 0 handling, dialog sizing, `Projects and sessions` single `QueryClient` and archive Undo, `Agent dashboard` shortcut and command palette, model fallback ordering and error card actions, Simplified Chinese localization, keyboard focus ring and tab bar layout/popover)
  - `packages/ui` (dialog `[data-fit]` precedence, disabled button cursor/opacity, error card `--card-accent` fallback, Simplified Chinese `ui.tool.shell`)
  - `packages/desktop` (`save-text-file` native save dialog IPC)

## Observed vs Expected Behavior

1. **#43**: Top-left `≡` app menu truncated the `Ctrl+B` shortcut next to `Projects and sessions` to `C` due to a fixed `width: 160px`. Expected: Menu width adapts to its items and displays the full shortcut.
2. **#44**: Executing a plugin skill slash command (e.g., `/vercel:status`) pasted the entire expanded `SKILL.md` template into the user message bubble. Expected: User bubble shows `/<command>`, while the expanded skill body is passed to the model as a synthetic text part.
3. **#45 & #46**: Settings → Plugins `Install your own` rendered duplicate `Cancel/Continue` action bars, showed a generic error for nonexistent local paths, lost input focus, kept the `Discover` tab underlined, and left error banners across tab/view switches; `Uninstall` used generic confirmation copy/title, inline unstyled checkbox, non-destructive button styling, and left package directories under `plugins/packages/` after uninstalling. Expected: Single confirmation view, specific path errors, focus restoration, action-specific destructive confirmation, and package directory cleanup.
4. **#47**: Provider connect dialog did not clear validation errors on input, accepted malformed API keys without validation, had excessive fixed height, and closed the entire Settings modal on completion. Expected: Clear error on input, validate key format, auto-fit height, and return to `Settings → Providers`.
5. **#48**: Exporting a session showed the `"Session exported"` toast before the OS save dialog completed and displayed `blob:oc://renderer/...` in the native dialog title. Expected: Use native Electron `showSaveDialog` IPC and only toast after the user confirms saving.
6. **#49**: Session titles remained at raw UTC ISO timestamps (`New session - 2026-...Z`) when turn 1 failed or in tabs/context panels, and custom models with `limit.context = 0` showed `Context Limit 0`. Expected: Strip default ISO suffixes consistently, retry auto-titling until a real assistant reply completes, and display `—` when context limit is `0`.
7. **#50**: Toolbar dialogs (`Command sandbox`, `Tasks`) had narrower widths or fixed heights (`[data-size="large"]` overriding `[data-fit]`), mixed `MB`/`MiB` units, full-width `Refresh status` button, mid-sentence `Session` capitalization, and Settings lacked a close (`×`) button. Expected: Consistent dialog sizing, units, button alignment, capitalization, and a top-right close button on Settings.
8. **#51**: `Projects and sessions` missed sessions and search results because `ServerShell` mounted a duplicate `<QueryProvider>`, and archiving a session had no Undo or restore path. Expected: Single shared `QueryClient`, fresh session index queries, and an Undo action on archive toasts.
9. **#52**: `Agent dashboard` shortcut `Ctrl+I` did not open the dashboard (and was unregistered on the New session page), and `Ctrl+K` command palette only showed 3 commands. Expected: Support both `Ctrl+\` and `Ctrl+I` across session and new-session pages, and list all enabled commands in the command palette.
10. **#53**: Fresh launches defaulted to internal codename model `GPT-5.6 Terra Pro`, `providers.defaultModel()` shadowed `recentModel()`, custom providers did not record their model as recent, and timeline error cards lacked visible accent/actions. Expected: Filter internal codenames (`daybreak-*`, `*-terra*`), prefer user-configured and recent models, and show `Connect provider` / `Choose model` actions on error cards.
11. **#54**: Simplified Chinese (`zh`) left `Preferences`, shortcut action names, and `Shell` untranslated; `Hooks` and `Side question` used awkward translations; English mixed `Customise` with US spelling; Models settings listed unconfigured providers before configured ones. Expected: Complete translations, US spelling consistency, and configured providers sorted first.
12. **#55**: Pressing `Tab` from the prompt input skipped the toolbar buttons (`Goal`…`Tasks`) and landed on controls without visible focus rings; titlebar tabs had a fixed `w-56` gap after short titles; tab hover popovers could stay stuck on screen. Expected: DOM Tab order reaches toolbar buttons after the composer with visible focus rings, tabs size to their content up to `max-w-56`, and hover popovers close reliably on pointer leave/down.
13. **#56**: `apexo frob` was treated as a directory path and exited with code `0`; `apexo memory list` exited without printing an error. Expected: Reject unknown commands/subcommands with a clear error and exit code `1`.
14. **#57**: `apexo export bogus` and `apexo session delete bogus` exposed raw schema errors; `apexo stats --days -5` accepted negative numbers. Expected: Validate `SessionID` with friendly `Session '<id>' not found.` message and reject negative `--days`/`--tools`.
15. **#58**: `apexo attach http://127.0.0.1:1` dumped TUI escape sequences and crashed with `TypeError: undefined is not an object (evaluating 'f.response.status')`. Expected: Probe connectivity before starting TUI and handle missing `legacy.response` cleanly.
16. **#59**: `apexo usage <sessionID> 999` printed INFO JSON logs to stderr without `--print-logs`. Expected: Only attach the stderr JSON logger in `native-local-host.ts` when `APEXO_PRINT_LOGS === "1"`.
17. **#60**: TUI status bar showed `OpenCode`, `--help` / `plugins` showed `Grok` / `Grok Build` branding, `debug config` pointed `$schema` to `cluster1900/apexo-grok`, `/usage` showed `1 turns` and split `$0.0000` across lines, sidebar Context showed `0% used` when limit was unknown, and `/debug` showed UTC ISO date. Expected: Unified Apexo branding, `cluster1900/apexo-code` schema URL, proper singular/plural and word wrapping, hidden `% used` when limit is unknown, and local date formatting.
18. **#61**: Exiting `apexo --mini --pure` under a clean `HOME` printed `[unknown-token] [Keymap] Unknown token "leader" in key sequence "<leader>e"` because `runtime.lifecycle.ts` called `unregisterKeymap()` before `shutdown(renderer)` (while `RunFooterView`'s `useBindings` was still mounted). Expected: Destroy the renderer (`shutdown(renderer)`) before unregistering the keymap token so active bindings unmount first without warning.
19. **#62**: `apexo mcp debug <missing-server>` printed `MCP server not found: <missing-server>` and exited with code `0`. Expected: Set `process.exitCode = 1` when the target server is missing or not a remote server.
20. **#63 & #64**: `apexo completion` emitted a Bash 4+ `mapfile -t` completion script that failed on macOS `/bin/bash` 3.2 (`mapfile: command not found`), ignored `apexo completion zsh`, failed under `zsh -f` (`command not found: complete` / `compdef`), and did not document `[shell]` in `apexo completion --help`. Expected: Provide a dedicated `apexo completion [shell]` (`bash` | `zsh`) command with Bash 3.2-compatible `while IFS= read -r` parsing, a Zsh completion script with automatic `compinit` fallback, and `--help` documentation.
21. **#65**: `apexo session list --format json` exited with `0` and empty stdout when no sessions existed. Expected: Output `[]` on stdout when `--format json` is requested and the session list is empty.
22. **#66**: Successful `apexo --help` and `apexo <command> --help` wrote all help text to `stderr` with `0` bytes on `stdout`. Expected: Write successful `--help` output to `stdout`, keeping error help output in `.fail(...)` on `stderr`.
