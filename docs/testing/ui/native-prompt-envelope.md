# BUG-20261015-090: Native App prompts used an obsolete flat request body

- Scope: App native-compatible Session prompt adapter.
- Observed: a real App workspace-profile Session creation returned HTTP 200, but the following prompt returned HTTP 400 with `Missing key at ["prompt"]`. The request contained flat `id`, `text`, `files`, and `agents`; no provider call occurred. This also affected ordinary native off Sessions.
- Expected: native prompts admit durable input using the current `{ id, prompt: { text, files, agents }, delivery, resume }` public contract, then follow the existing native execution path.
- Root cause: `createCompatibleApi` forwarded native prompt calls to the older vendored promise client rather than adapting its input to the current endpoint. Sandbox creation exposed this existing mismatch; sandbox enforcement was not the cause.
- Fix: only the native prompt implementation now uses the current generated v2 SDK. It preserves message identity, files/agent mentions, delivery, admit-only controls, credentials and errors, and maps the real admission receipt into the App's existing result type. Legacy prompt routing remains unchanged. No provider retry or alternative execution engine is introduced.
- Verification: in `packages/app`, `bun test --conditions=solid --preload ./happydom.ts src/utils/server-native-prompt.test.ts src/utils/server-skills.test.ts` passes 3 tests / 18 assertions; `bun typecheck` passes. In `packages/apexo`, `bun script/grok-native-sandbox-ui.mjs browser --locales` passes seven checks and exactly three provider calls for off/workspace/read-only native Sessions. HTTP request evidence confirms the nested prompt envelope and HTTP 200 admission.
- The transport regression fixture initially needed CORS preflight handling under HappyDOM, then hit the existing DOM/native Response construction mistake recorded in [BUG-20261014-124](../test-fixtures/protocol-health-dom-response.md). It now serves explicit bytes through `node:http` and closes the server once after consumed request bodies.
