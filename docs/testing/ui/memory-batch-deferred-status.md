# BUG-20261015-378: Settled batch deferrals displayed a replay instruction

- **Scope:** App/Desktop Memory operation list and detail, compatibility Memory Work, and shared terminal views.
- **Status:** Fixed and verified on the integrated shared source and rebuilt App/Desktop artifact.
- **Occurrences:** One observed product defect during final batch UI acceptance.
- **Observed:** A batch had processed one note and durably deferred another. The native Desktop detail displayed “This operation requires an explicit retry. Its original request will be preserved.” beside the new Run Dream action. The terminal used “Explicit retry required”. Exact retry correctly retained the completed claim without provider work, so that instruction did not advance the remaining note.
- **Expected:** Show deferred and unplaced-archive counts as the settled result summary, with Run Dream available to start a new operation. Keep exact retry semantics unchanged.
- **Reproduction:** From `packages/apexo`, run `bun script/grok-native-memory-batch-dream-ui.mjs native --deferred`. Inspect the first completed partial result, then exact retry and the independent next Dream. The retained before screenshot proves the misleading paragraph even though the earlier functional probe passed.
- **Root cause:** The views mapped every `retry_required` result to a generic recovery instruction without accounting for durable per-note deferrals.
- **Fix:** For `retry_required` with positive deferred counts, use the existing localized batch outcome as status/list summary. Render detail counts once and retain the existing gated Run Dream action. Apply the same distinction in terminal summaries. Memory Work preserves running-state precedence even if a partial store update retains an older result. Other statuses retain their original status text and separate counts, including failed, cancelled, timed out, and conflict. No status, API, locale key, permission, or execution changes.
- **Verification:** Shared App and TUI package typechecks, App build, and Desktop build passed. From `packages/apexo`, `bun script/grok-native-memory-batch-dream-ui.mjs browser --deferred` and the same command with `native --deferred` each passed six checks with three Dream calls. Actual browser/native screenshots were inspected: the detail count appears once, the misleading retry paragraph is absent, and Run Dream remains visible. Exact retry sends no new provider request; independent Dream advances the pending note and the third unplaceable result is shown correctly. `bun script/grok-native-memory-batch-dream-tui.mjs`, the same with `--fullscreen`, and with `--fullscreen --narrow` each passed four checks with three calls. Mini 100×40 and fullscreen 100×40 / 80×24 screens were inspected. All five process trees exited and were reaped; 3,647 source/artifact hashes were unchanged across the sequence. Compatibility Memory Work receives no native batch metadata today; its defensive presentation change passed types, but is not claimed as a new compatibility executor capability.
- **Constraint:** No recurrence promotion; one episode.
