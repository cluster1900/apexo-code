# BUG-20261014-108: Identical host hooks from several sources executed repeatedly

- **Scope:** Host hook discovery, effective inspection identity, and existing host dispatch adapters.
- **Observed:** Static comparison found that Apexo concatenated supported global configuration/file and trusted project sources without duplicate resolution. Identical configured hook content could therefore execute more than once.
- **Expected:** Resolve duplicates using canonical event, raw command, raw URL, and configured matcher before environment expansion. Configuration precedes files; equal-authority sources retain the first copy. Timeout and environment do not make a duplicate distinct. Preserve the winning handler's original source identity.
- **Reference:** Pinned `xai-grok-hooks/src/discovery.rs` assembly and `registry_from_specs_deduped`; plugin-layer replacement separately appends plugin hooks and is outside this host-source change.
- **Reproduction:** Put the same command under the same canonical event in global config TOML and a global JSON hook file, with different environment values. Submit one actual Session prompt and inspect the command trace.
- **Root cause:** Discovery expanded each source independently and the adapter executed every resulting handler, without a raw-content identity boundary.
- **Fix:** Resolve supported host duplicates before expansion. Preserve original names using nonenumerable internal metadata and use that name consistently in sanitized inspection and all host dispatch paths. Distinct raw expressions, URLs, events, and matchers remain distinct. Unsupported/malformed handlers do not claim a valid duplicate identity. Exact project trust remains authoritative. Installed bundle handling and managed-policy authority are unchanged.
- **Verification:** Applied only after staged base hashes matched and patch application check passed. Focused/related tests passed 26 tests / 135 assertions; package typecheck and CLI four-scenario checks passed. The first installed comparison failed because installed Grok 1.0.52 retained config/file copies with different environment/timeout, whereas the pinned source excludes both from duplicate identity. The identical-environment/timeout control was deduplicated by the installed runtime; copies with changed settings remained. The installed comparator passed all 20 scenarios with this explicit distinction, including preserved original handler identity. Apexo follows the pinned raw-content rule. The refreshed production Desktop artifact passed all four deduplication scenarios.
- **Occurrences:** One static contract finding; no historical runtime count is inferred.
