# BUG-20261014-159: Native server rejects Desktop mutation preflight

- Scope: native-only Server routes used by the macOS Desktop renderer and other allowed cross-origin App clients.
- Observed: after correctly registering the external native server, Desktop loaded the Session and opened Goal. Its passive Goal GET returned 200 with `Origin: oc://renderer`. Creating the Goal produced an OPTIONS request to `/api/session/:sessionID/goal` with the same origin; the server returned 404. Electron reported that the preflight response did not have an HTTP success status. No Goal POST or provider call followed, and the panel showed its operation error. The fixture eventually timed out waiting for execution.
- Expected: allowed origins receive a successful preflight with the necessary CORS response headers, allowing authenticated mutation requests to reach their native handlers. Disallowed origins remain denied.
- Reproduction: run `bun ./script/grok-native-goal-ui.mjs native` from `packages/apexo` against the native-only server with a fresh built Desktop artifact. The fixture registers its external connection, creates a Session through HTTP, opens Goal, and clicks Create and start goal. Alternatively, send OPTIONS with `Origin: oc://renderer`, `Access-Control-Request-Method: POST`, and `Access-Control-Request-Headers: content-type` to a native Goal URL.
- Root cause: `packages/server/src/routes.ts` builds the typed native API without CORS middleware. The production native CLI uses those routes directly. The compatibility server separately installs CORS middleware, and the earlier browser fixture used a same-origin proxy, so those checks did not exercise this boundary.
- Fix: native routes now provide the shared Server CORS middleware using the existing origin policy and `CorsConfig`. The preflight Vary correction is shared with the compatibility server through a re-export; both Origin and requested-header cache keys are preserved. Preflight success does not bypass normal route authentication.
- Verification: the initial native request trace and Electron console agree on OPTIONS 404, with no provider request. After the fix, `bun test test/server/native-cors.test.ts test/server/httpapi-cors-vary.test.ts` from `packages/apexo` passed seven tests/26 assertions. They verify Desktop/local browser preflight, readable native responses, rejected untrusted origins, preserved Vary fields and a 401 mutation response despite valid preflight. Server package `bun typecheck` passed. The subsequent actual macOS Electron runs passed Goal seven checks, Feedback twelve checks and Hooks eight checks including Simplified/Traditional Chinese panels. They exercised native mutations, local downloads and explicit snapshot reload through the corrected native server. Screenshots were inspected and all owned processes reaped. Apexo package typecheck also passed. The preceding complete 271-scenario HTTP gate passed before this CORS addition and is not claimed to verify it.
