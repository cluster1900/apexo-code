# BUG-20261102-001: Native TUI worker startup, logger suppression, interactive `--sandbox` routing, and sandbox profile validation

- Scope: `packages/apexo/src/cli/tui/worker.ts`, `packages/apexo/src/cli/native-local-host.ts`, `packages/apexo/src/cli/native-local.ts`, `packages/apexo/src/cli/native-local-fullscreen.ts`, `packages/apexo/src/cli/cmd/init.ts`, `packages/apexo/src/cli/cmd/run/footer.ts`, `packages/apexo/src/cli/cmd/run/footer.view.tsx`, and `packages/tui/src/component/prompt/index.tsx`.
- Observed:
  1. Launching fullscreen native TUI (`apexo --sandbox <profile>`) intermittently timed out with `Operation timed out after 20000ms` during `client.call("start", undefined)`.
  2. Launching interactive Mini TUI (`apexo --mini --sandbox <profile>`) printed raw Effect `INFO` logs (`project copy refresh done`, `booting location services`) directly onto the interactive terminal screen unless `headless = true` was passed to `createNativeLocalHost`.
  3. Running `apexo run --interactive --sandbox <profile>` failed with `A new prompt or file is required for native headless execution` instead of opening the interactive UI.
  4. Running `apexo init` in a Python project with `pyproject.toml` and no `requirements.txt` generated `pip install -r requirements.txt` in `AGENTS.md`.
  5. Typing `/sandbox does-not-exist` in Fullscreen TUI or Mini TUI accepted the unknown profile name and displayed a success message (`New session sandbox profile set to does-not-exist`), and in Mini TUI background `stream.patch` idle polls (`status: ""`) cleared active footer notices within 250ms.
- Expected:
  1. Early RPC requests posted immediately after `createTuiWorker(...)` must be delivered once the worker module finishes its dynamic import and registers `Rpc.listen(rpc)`.
  2. `createNativeLocalHost` must suppress default Effect console logging unless `APEXO_PRINT_LOGS=1` is explicitly enabled, regardless of whether the host runs headless or in an interactive terminal.
  3. `apexo run --interactive --sandbox <profile>` must enter the interactive Mini TUI rather than falling through to headless execution.
  4. `apexo init` in a `pyproject.toml`-only Python repository must generate `pip install -e .` instead of referencing a non-existent `requirements.txt`, only emit `pytest` / `ruff` / `mypy` / `pyright` when backed by project configuration evidence (otherwise prompting the user to fill in their test command), its `.apexo/sandbox.toml` `[filesystem]` deny list must cover both root and subdirectory `.env` / `.env.*` files (`[".env", ".env.*", "**/.env", "**/.env.*"]`), its `AGENTS.md` usage instructions must explicitly document `--sandbox pkg-install`, `--sandbox ci-verify`, `--session-protocol native`, that `[filesystem]` `deny` rules apply only when a non-`off` command sandbox profile is enabled, and that `/sandbox <profile>` only sets the profile for future sessions created with `/new`; when `Agents.md` already exists on a case-insensitive filesystem (macOS APFS), `[skipped]` / `[overwritten]` output must report the actual on-disk filename (`Agents.md`); and when `AGENTS.md` is a symlink, `init --force` must write through to the symlink target while reporting `AGENTS.md` rather than creating a file named after the symlink target in the workspace root.
  5. `Seatbelt.prepare` and `Bwrap.prepare` must preserve sanitized non-workspace absolute directories from `process.env.PATH` after core POSIX system directories (`/usr/bin`, `/bin`, `/usr/sbin`, `/sbin`) so user-installed package managers and toolchains (such as `pnpm`/`node` under `~/.nvm`, `~/.cargo/bin`, `~/.local/bin`) are resolvable inside `pkg-install` and `workspace` sandboxes.
  6. `/sandbox <profile>` in both Fullscreen TUI and Mini TUI must validate the requested profile against the sandbox catalog, report unknown profiles along with available profile names (and in compatibility mode instruct the user to start with `--sandbox <profile>` or `--session-protocol native` instead of saying the argument was ignored), explicitly state in the confirmation notice what sandbox profile the current session is still using and to run `/new` to apply the new profile, warn when `--session` / `--continue` is combined with a mismatched `--sandbox`, keep Mini TUI status notices visible across background idle `stream.patch` polls without middle-truncating available profiles (`avai...vbox`), include available profile names in `CommandSandboxPaths.resolve` (`Unknown command sandbox profile: <profile>. Available profiles: ...`), and fit the full `Available profiles` list inside an `80×24` Fullscreen TUI dialog without clipping.
  7. `Gemini.fromRequest` in `packages/llm/src/protocols/gemini.ts` must lower `responseFormat` (`responseMimeType` and `responseSchema`) into `generationConfig` even when `tools` (`functionDeclarations`) are enabled on the request.
- Reproduction:
  1. Spawn `apexo <workspace> --sandbox pkg-install` in a PTY and observe `runNativeLocalFullscreen` calling `client.call("start", undefined)` while `worker.ts` is awaiting `import("./worker-native")`.
  2. Spawn `apexo <workspace> --mini --sandbox pkg-install` in a PTY and inspect the rendered terminal buffer after startup.
  3. Run `apexo run --interactive --sandbox workspace` in a terminal without a prompt argument.
  4. Run `apexo init` in a directory containing only `pyproject.toml` and inspect `AGENTS.md`.
  5. Run `/sandbox does-not-exist` in Fullscreen TUI and Mini TUI.
- Root cause:
  1. `packages/apexo/src/cli/tui/worker.ts` used top-level `await import("./worker-native")` / `await import("./worker-compatibility")` before `Rpc.listen(rpc)` assigned `onmessage`, so `MessageEvent`s dispatched while the dynamic import was resolving were dropped.
  2. `packages/apexo/src/cli/native-local-host.ts` only attached `Logger.layer(loggers, { mergeWithExisting: false })` when `headless` was `true`, leaving Effect's default stdout logger active in interactive local modes.
  3. `runNativeLocalMini` in `packages/apexo/src/cli/native-local.ts` only checked `if (!input.mini)` before entering the headless path, ignoring `input.interactive`.
  4. `detectStack` in `packages/apexo/src/cli/cmd/init.ts` used `pip install -r requirements.txt` whenever neither `uv.lock` nor `poetry.lock` existed, without checking whether `requirements.txt` existed.
  5. `/sandbox <arg>` in `packages/tui/src/component/prompt/index.tsx` and `packages/apexo/src/cli/cmd/run/footer.view.tsx` called `select(arg)` without checking `catalog()`, and `RunFooter.event` in `packages/apexo/src/cli/cmd/run/footer.ts` cleared `noticeTimeout` whenever `stream.native.ts` emitted its 250ms `{ phase: "idle", status: "" }` poll.
- Fix:
  1. Buffer incoming `onmessage` events in `packages/apexo/src/cli/tui/worker.ts` before the top-level dynamic import and replay them into `onmessage` once the worker module finishes loading.
  2. Always provide `Logger.layer(..., { mergeWithExisting: false })` in `createNativeLocalHost` so default Effect logs do not write to the terminal unless `APEXO_PRINT_LOGS=1` is set.
  3. Check `if (!input.mini && !input.interactive)` in `runNativeLocalMini` (`packages/apexo/src/cli/native-local.ts`).
  4. Check `existsSync(path.join(directory, "requirements.txt"))` in `packages/apexo/src/cli/cmd/init.ts` and use `pip install -e .` when `pyproject.toml` is present without `requirements.txt`.
  5. Validate `/sandbox <arg>` against the sandbox catalog in `packages/tui/src/component/prompt/index.tsx`, `packages/apexo/src/cli/cmd/run/footer.view.tsx`, and `packages/apexo/src/cli/native-local-fullscreen.ts`; wrap `selected.create(...)` in `Prompt.submit()` with `.catch(...)` error toast handling; and preserve active `noticeTimeout` notices in `RunFooter.event` when background `stream.patch` events send `status: ""`.
- Verification:
  - Verified direct `createTuiWorker(..., "native")` + `client.call("start", undefined)` startup succeeds deterministically.
  - Verified full PTY interactive human-simulation across `apexo init` (JS/Bun and `pyproject.toml`-only Python), `apexo run --interactive --sandbox pkg-install`, and `apexo --sandbox pkg-install` (including `/sandbox does-not-exist` rejection with available profiles, `/sandbox` dialog/panel, `p` key profile cycling, `/new`, and session creation).
  - Verified `bun test ./test/cli/init-and-sandbox-selection.test.tsx` and `bun run typecheck`.
