# BUG-20261015-366: Sleeping automatic Dream held the Location reload guard

- Scope: native automatic legacy Dream timer lifetime and Location runtime reload.
- Observed: the initial automatic Dream draft wrapped its entire periodic loop, including sleep, in `LocationRuntimeGuard.use`. A positive interval kept the Location busy between checks, preventing plugin/configuration reload. The first real-guard regression failed with expected Success versus Failure after the guard remained busy throughout the bounded observation.
- Expected: actual preparation, admission and execution own the Location guard; a sleeping timer must permit reload. A timer armed by a retired Location runtime must not continue using that old service closure after reload.
- Root cause: ownership appropriate for a finite automatic flush worker was extended to the lifetime of a periodic timer. Merely removing the guard would still leave a cached MemoryLifecycle service closure crossing runtime replacement.
- Fix: limit the guard to initial schedule preparation and each check/admission. The canonical operation worker retains its independent guard. Resolve the Location service on every tick and terminate the timer if its runtime identity differs from the one that armed it. Keep the existing Session activity epoch, mode cancellation and worker join ownership across sleeps.
- Reproduction: enable a one-second Dream interval and disable automatic flush; seed an eligible source, complete a real Session provider turn and wait for the automatic Dream receipt. Call the real `guard.idle` between checks. After reload, add another source without another live activity and verify that the retired timer does not consolidate it.
- Verification: `bun test test/v2/memory-automatic-dream-native.test.ts --test-name-pattern 'sleeping automatic Dream'` from `packages/apexo`, pinned Bun 1.3.14: before fix, zero pass / one fail / two assertions; after fix, one pass / six assertions. The final assertions prove idle reload succeeds, the Location service identity changes, the old timer stays passive and new live activity uses the reloaded runtime. The expanded automatic/manual/V2/storage gate passes 46 tests / 225 assertions. Final Core and Apexo package typechecks and the rebuilt Desktop production build pass. Rebuilt Desktop positive/restart acceptance passes five checks, and failed-source/restart acceptance passes three checks. Browser and native Electron window each pass four checks, including visible periodic completion. The earlier build remains explicitly pre-fix evidence.
- Independent occurrences: One confirmed timer/guard lifetime defect; no recurring constraint is promoted.
