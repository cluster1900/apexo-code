# BUG-20261015-359: Native Shell omits configured command prefix and output character limit

- **Scope:** Native Bash configuration, execution authority and model-output settlement.
- **Observed:** `cmd_prefix` and `output_byte_limit` were absent from native/compatibility configuration schemas and silently discarded. Native commands executed without the configured prefix, and output previews ignored the configured character budget.
- **Expected:** The actual prefixed command passes existing permission and sandbox checks and is captured in an immutable process receipt. Host output configuration bounds command output by Unicode code points without weakening global byte/line caps or removing receipt metadata.
- **Reproduction:** From `packages/apexo`, run `bun test --timeout 30000 test/config/native-shell-config.test.ts test/v2/shell-prefix-output.test.ts` against the prior configuration/executor. The coherent negative control has two passing and nine failing tests: decoded settings disappear, receipts contain only the original command, prefix effects are absent, and configured output caps are ignored.
- **Root cause:** The native Shell implementation had not ported these host configuration fields or their execution/output boundaries. The fixed reference's `BashParams` is injected host configuration; `BashToolInput` does not expose either field as a model argument.
- **Fix:** Extend the existing shared configuration schema. Capture the command and output limit once per invocation. Chain the prefix before the model command, then use that entire string for path advisories, exact permission resources, sandbox preparation and process requests. Add a typed, internal output-policy channel to opaque `Tool.make` settlement; Registry passes it to the existing ToolOutputStore. The store retains the full captured command output, renders a Unicode head/tail preview, then applies its existing generic byte/line limit. Owned Bash output separates command text from receipt metadata. Policy metadata is omitted from advertised output schemas and public/model structured output.
- **Verification:** The focused lifecycle union passes 25 tests / 247 assertions, including configured-command denial with zero execution, prefix cwd/environment and separator behavior, prefix cancellation, read-only sandbox enforcement, multibyte/zero output limits, retained output and global bounding. Source CLI passes two real cases. Isolated installed 1.0.52 passes two cases with four conversation and nine auxiliary requests; its catalog confirms output limit is host-only. Canonical schema generation updates only `schemas/config.json`. Core and Apexo typechecks pass. Rebuilt Desktop remains an integration gate.
- **Occurrences:** One confirmed missing native capability; no recurring-rule promotion.
