# BUG-20261014-214: Instance shutdown waited on an unsettled load

- **Scope:** Compatibility InstanceStore lifecycle used by the mixed HTTP server.
- **Observed:** The complete HTTP authorization exercise passed all 277 assertions but remained alive in application disposal. Its logs showed a worktree Instance load still in progress when shutdown began. An independent full authorization run reproduced the same shutdown hang. Smaller route subsets could exit normally, so their passing assertions did not resolve the full-gate failure.
- **Expected:** Closing the owning application scope interrupts unfinished Instance initialization and settles every published load or reload entry, allowing all waiters and disposal to finish.
- **Reproduction:** Run `bun script/httpapi-exercise.ts --mode auth --fail-on-missing --fail-on-skip` from `packages/apexo`. The valid-credential probes can start asynchronous worktree initialization near shutdown. Deterministic cases in `test/project/instance-shutdown.test.ts` close the owner during initial bootstrap, while reload waits for a previous load, and during reload's disposer prelude.
- **Root cause:** Load completion captured the bootstrap exit but performed cache removal and Deferred completion in an interruptible region. Owner cancellation could skip settlement, leaving `disposeAll` waiting forever. Reload additionally performed previous-entry waiting and disposal outside that completion boundary, so cancellation before bootstrap had the same outcome. This is distinct from the Location-map identity errors in BUG-20261014-154; the timing of the integrated runtime exposed an existing lifecycle hole.
- **Fix:** Put each entire owned load/reload action inside an interruption mask, restoring interruption only around the actual action. Cache cleanup and Deferred settlement then complete uninterruptibly for success, failure, or interruption. Bootstrap and reload cleanup remain interruptible; slow initialization is not protected from shutdown.
- **Verification:** All three deterministic cases failed before the fix. The corrected shutdown and existing InstanceStore suites passed 12 tests with 26 assertions, including waiter failure settlement. The complete authorization exercise passed all 277 scenarios and exited successfully after disposal. Final package type and complete mixed-route gates are tracked by the coordinated verification checkpoint.

This is one observed lifecycle occurrence with diagnostic reruns and three deterministic regression cases, not three independent recurrences.
