# BUG-20261014-104: Stopping an old workflow interrupted an unrelated Session drain

- Scope: Workflow control after process restart and process-local execution ownership.
- Observed: A production CLI fixture killed a running workflow process, reopened its durable records, then held a new ordinary prompt on the same Session. Stopping the old workflow removed the new ordinary drain from the active Session registry.
- Expected: A durable old run can be marked stopped, but cannot interrupt work it does not own in the current process.
- Reproduction: From packages/apexo, run `bun script/grok-workflow-native.mjs cli --ownership` against the implementation before this fix.
- Root cause: Control.stop interrupted by Session ID whenever the stored run said pending or running. Durable state was mistaken for live process-local ownership.
- Fix: The existing global WorkflowStore service tracks exact live run claims. Engine scopes acquire and release claims; duplicate engine instances share them. Control passes an exact-run ownership predicate to the authoritative Session coordinator. The coordinator evaluates it synchronously with selecting the active fiber, closing the check-to-capture window before interruption. No automatic recovery or provider retry is introduced.
- Verification: Before the fix, the real CLI ownership assertion failed after the stop request. The focused suite passed 12 tests and 53 assertions. `bun script/grok-workflow-native.mjs cli --ownership` passed six scenarios with 12 provider calls, including preserving a held ordinary drain while stopping an old run. The rebuilt Desktop ownership fixture also passed six scenarios and 12 calls. The subsequent deterministic coordinator regression constructs a delayed stop, completes its old drain, starts a successor, and then executes the stop. Before the guarded capture fix the successor was interrupted; afterward it remains active, and an unconditional interrupt still waits for its finalizer. The updated Workflow suite passed 14 tests and 61 assertions; combined with native Session integration it passed 15 tests and 88 assertions. Core typecheck passed. Updated CLI acceptance passed seven scenarios and 12 calls. The rebuilt Desktop acceptance of the final guarded-capture refinement also passed seven scenarios and 12 calls.
- Occurrences: One reproduced ownership failure.
