# BUG-20261015-261: Headless signals could not stop held startup HTTP

- Status: corrected and integrated; actual compiled shared startup/admission cancellation passes.
- Scope: native headless startup and admission transport, not the native execution coordinator.

A real HTTP proxy held the native agent catalog response and, independently, the response after a real resume:false admission committed. SIGTERM only set the CLI's stop flag. Neither child exited within twelve seconds, so the fixture had to kill each with SIGKILL/137. No provider request occurred; the committed input remained admitted. The flag was not observed because execution was still awaiting an unbounded request before the interrupt loop.

Startup get/list/catalog/create/selection/admission requests now carry a ten-second bound and a caller stop signal. The advisory SSE handshake is bounded and its owned reader is aborted/joined on stop. Ordinary receipt/history requests are also stop-aware. Cleanup uses a separate bounded signal, never the already-aborted foreground request owner.

The adapter marks admission attempted before issuing the request and retains its canonical Session/input identity. An aborted response does not establish that admission failed. Stop conditionally interrupts only that exact input. A confirmed receipt permits signal exit130/143; unknown/404 while admission may still commit remains unconfirmed exit1 with the identity for inspection. No new prompt, provider retry or Session-wide cancellation is used. Local host disposal remains the final joined local owner boundary, but cannot override an unknown durable admission to a successful signal exit.

`bun script/grok-native-headless-startup-stop.mjs` first reproduced both twelve-second hangs. After correction it passed three real-server cases with zero provider requests: held catalog stopped143; committed admission with held response became withdrawn and stopped143; a deliberately late admission received404 during cleanup and stopped1, then committed as admitted after the fixture released it. The fixture proved that pending state and explicitly cleaned it up. Observed successful stop latencies were25ms,80ms and48ms respectively; these samples are evidence of this run, not a timing guarantee. Existing active cancellation, supersession and unconfirmed503 cases remain separate regression coverage.

The final ordered sources passed the same three startup cases again, the existing three active cancellation/supersession cases, local15/20 and mixed-native17/21 matrices, five local file checks, seven startup rejection checks, the21-test/120-assertion/37-snapshot focused gate, and `bun typecheck` in packages/apexo. All owned processes exited and were reaped. These are private-source results; no shared or packaged acceptance is implied.

After shared integration and a fresh standalone CLI build, the same startup-stop command passed all three cases with zero provider calls. The compiled catalog and committed-admission cases exited 143; the unknown/late-admission case exited one with explicit unconfirmed-cleanup guidance, then retained the expected admitted receipt until fixture cleanup. Observed latencies were 11, 29 and 14 ms respectively, without changing deadlines. Compiled cancellation/supersession races also passed three checks / three requests; compiled local15/20, files7/4, rebuilt mixed Desktop17/22 and seven pre-start rejection cases passed. All owned processes were reaped. See [the shared command set](../../native-headless-cli.md#shared-integration-checkpoint).
