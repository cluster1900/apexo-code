# BUG-20261114-F02-N2-01: Normal native mini shutdown dumps AbortError

- **Scope:** Native terminal streaming and the generated legacy SDK event reader; audit N2-01.
- **Observed:** Double Ctrl+C exits mini attach with code 0 but prints a DOMException/AbortError object and stack. The audit stack points at the final aborted-turn check; the first remediation probe still prints a stack originating at transport close.
- **Expected:** Intentional transport shutdown joins its readers without terminal error output; genuine stream failures remain visible.
- **Reproduction:** Run `bun script/permission-review-tui.mjs` from `packages/apexo`, execute a native turn and quit with two Ctrl+C presses. Inspect raw terminal output after exit, not only the live framebuffer. Pure/mixed mini reproduce; native-local transport has different fetch behavior.
- **Root cause:** The turn treats an owned shutdown abort as a failed prompt. Separately, the generated SSE reader calls `reader.cancel()` inside a synchronous catch, leaving its rejected promise unhandled when fetch is aborted. Catching the turn alone does not fix that rejection.
- **Fix:** End an intentionally aborted native prompt normally and preserve non-abort failures. Patch the canonical SDK generator to consume the cancellation promise, then regenerate the SDK. No generated source was edited manually and no global rejection handler was installed.
- **Verification:** `bun test test/sdk/native-sse.test.ts` exercises three actual HTTP subscriptions, each blocked on its next read when aborted. The test runner receives no unhandled rejection. The **97-test / 476-assertion** combined regression passes. Real mini/fullscreen pure/mixed PTYs pass **11 checks each** and assert exit code 0 plus no `DOMException`/`AbortError` in complete raw output. Native-local mini exits cleanly as part of its **8-check** CLI script. SDK `check:generated` passes after regeneration.
- **Occurrence accounting:** The turn and reader observations are two boundaries in this one reported shutdown defect. No recurring constraint or invented occurrence count is added.
- **Active-turn probe:** `permission-review-tui.mjs --exit-active` also passes **12 checks**: it types an actual prompt, waits for its permission blocker, then quits with two Ctrl+C bytes and inspects the entire raw output after exit. The first fixture attempt waited for an exit hint that the active permission panel does not render; the corrected probe sends the documented two-key gesture after observing the blocker, without requiring an invisible hint. This is a fixture expectation correction, not a product change.
