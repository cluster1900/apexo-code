# BUG-20261015-206: Attachment compatibility alias leaked into media generation configuration

- **Status:** Corrected; the complete compatibility configuration file passes 36 tests and 112 assertions. The complete repository gate still needs a new run after the separate Worker fixture correction.
- **Scope:** `ConfigV2Compat.lower` and V1 configuration schema decoding. One root-cause episode; two failing snapshots are not independent recurrences.
- **Observed:** The full unit gate failed the `settings` and `settings-precedence` compatibility fixtures because an extra `media: {}` survived decoding. A generation-only `media` object could also be interpreted as an empty attachment alias.
- **Expected:** Translate the native `media.image` attachment alias while preserving explicit legacy attachment precedence. Preserve independent media generation/storage settings, and do not invent an empty unrelated configuration section.
- **Reproduction:** From `packages/apexo`, run `bun test test/config/v2-compat.test.ts`. The original aggregate failed both existing settings fixtures. A generation-only object and a combined attachment/generation object exercise the overlapping field names.
- **Root cause:** The old compatibility adapter left the entire native attachment container in `result.media`, relying on the old V1 schema to discard that unknown field. Adding genuine media generation configuration made `media` a recognized optional container. Its decoder discarded the unknown `image` child but retained an empty object. The alias adapter also decoded generation-only settings as an empty attachment object.
- **Fix:** Normalize the attachment alias only when `media.image` is present. Remove that consumed alias while retaining other media fields for normal schema validation; omit the container when no fields remain. Do not update snapshots to accept the leak or discard invalid generation values.
- **Verification:** The existing settings and precedence snapshots pass unchanged. The added real normalization/schema regression verifies generation-only settings, combined attachment/generation settings and rejection of a malformed generation model override. `bun test test/config/v2-compat.test.ts` passed 36 tests / 112 assertions with exit zero.
