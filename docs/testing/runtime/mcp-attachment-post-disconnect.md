# BUG-20261015-334: Bun POST disconnect does not notify the Node HTTP request owner

- Scope: Pending native MCP preparation served through Effect's Node HTTP adapter on pinned Bun 1.3.14.
- Observed: Both pure and mixed host tests completed ordinary text/image/PDF preparation, but interrupting the Fetch-backed HTTP caller did not produce MCP cancellation or cooperative cleanup. Explicit `node:http` request destruction reproduced the same outcome. Direct Session deletion did interrupt the registered preparation owner and produced separate MCP cancel/cleanup evidence.
- Expected: Explicit product cancellation must stop and join the Session-owned work even when disconnect events are unavailable.
- Isolation: A minimal server consumes a POST body and holds the response. After destroying a raw TCP client, Bun reported only `body.read` within the bounded observation period. The same script under installed Node reported `body.read`, `response.close`, and `socket.close`. Effect's Node server adapter interrupts request fibers from `ServerResponse.close` before response completion.
- Reproduction: Run `bun script/grok-mcp-attachment-cancellation-probe.mjs` and `node script/grok-mcp-attachment-cancellation-probe.mjs` from `packages/apexo`. Run the original HTTP preparation fixture with disconnect as its sole cancellation mechanism.
- Classification: This is an observed runtime/adapter boundary limitation after consuming a POST body. It is distinct from BUG291's GET fixture, which did observe socket close and merely listened to the wrong event. No shared root cause or recurrence count is inferred.
- Status: Transport behavior remains unresolved. The Session-bound reserve/execute/status/cancel operation API now supplies explicit product cancellation. Pure and mixed real HTTP tests pass two cases / 44 assertions, independently observing cooperative MCP cleanup after the cancel response. Actual mini and fullscreen picker entrypoints each pass four checks, including a held-read explicit cancellation. No adapter repair is claimed.
- Boundaries: MCP SDK abort rejects its local request and sends a cancellation notification without a remote acknowledgement. Joining the local Session owner does not prove arbitrary remote server work has stopped. Cooperative fixture cleanup is observed independently.
