# BUG-20261015-327: Automatic Memory publication could outrun a newly admitted prompt

- Scope: native legacy automatic flush, durable prompt admission, and the final Memory write.
- Observed: the automatic provider completed while the prompt-admission fence was held. A new prompt queued first and was durably admitted after release, but the older flush still completed and published instead of being cancelled.
- Expected: a new prompt that wins admission invalidates prior automatic work before publication. If a short commit wins the same fence first, admission waits for that commit and then joins its owner. Locks held while waiting for external maintenance must not block admission.
- Reproduction: complete one real provider turn, hold the idle flush response, hold the Session input-admission fence, queue an admit-only prompt, release the old response, then release the fence. Without final publication fencing the regression observes `completed` instead of `cancelled`.
- Root cause: the automatic epoch was checked before worker execution but not ordered against durable admission at the final uninterruptible Memory commit. Cancelling the worker after admission could not undo a commit already entering that boundary.
- Fix: the Session-owned operation passes its captured Claim and current-epoch predicate to the legacy leaf. After acquiring maintenance and destination leases, the leaf takes the same short input-admission fence and checks the predicate inside the mode commit. Prompt invalidation remains synchronous under admission; worker interruption and joins occur after releasing that fence. The leaf does not import SessionV2. Explicit operations do not acquire the automatic admission fence.
- Verification: from `packages/apexo`, pinned Bun 1.3.14, `bun test test/v2/memory-legacy-native.test.ts --test-name-pattern 'durable prompt admission fences completed' --timeout 30000`: the controlled pre-fix run failed (one test; receipt completed), and the fixed run passed (one test / four assertions). The fixed assertion requires a cancelled receipt, an absent Memory sessions file, and exactly the ordinary plus automatic provider request. The final serial legacy/V2 lifecycle run subsequently passed 56 tests / 277 assertions, including all 42 legacy cases, explicit flush and held maintenance prompt/disable/clear/deny cases. Core and Apexo types passed. This is one demonstrated occurrence; no recurring constraint is promoted.

## Automatic legacy Dream regression coverage

The native automatic Dream implementation applies the same admission fence and captured epoch contract. A real CLI observer pauses inside the actual uninterruptible filesystem publisher after validation, and observes the real SQLite insertion for a concurrent admit-only prompt. Its deliberate negative control removes only the final fence: the probe fails with `admitted-before-publication` and the old output is still written. The production-fence run passes; the new input is inserted only after the prior publication is released. The observer neither replaces provider results nor mocks storage writes. Separately, a focused real-lock case cancels and joins an automatic Dream after its publication payload is durable but before it acquires the destination lease, leaving no output file.

These are new regression controls for the existing ordering requirement, not an independently discovered production omission: the automatic Dream draft included this fence from its first implementation. The historical occurrence count is unchanged. After the independent timer guard fix, the focused automatic/manual/V2/storage gate passes 46 tests / 225 assertions. Final types and Desktop acceptance are tracked in the automatic Dream feature document.
