# BUG-20261015-150: Native terminal fresh-session bootstrap

- **Scope:** Off-tree native mini/fullscreen transport authoring. Separate boundaries below belong to this acceptance episode; they are not counted as recurrent bugs.
- **Observed Location failure:** A real fullscreen fresh-session request selected directory `/` even though attachment specified the fixture workspace. The subsequent prompt was durably admitted in the wrong Location and did not reach the configured fixture model.
- **Cause:** The adapter treated Project.Current.directory as the current working directory. It is the project root; the global project's root is `/`. This was not a guessed server startup delay.
- **Fix:** Preserve the resolved Location returned with the canonical Agent catalog and use its directory for current placement. Keep Project.Current.directory only as project/worktree identity. Never infer placement from a Session ID or retry a native request through compatibility routes.
- **Model selection:** Fresh mini Sessions previously had no selected model in the display. The adapter now follows the existing App/terminal order using the explicit choice, persisted Session model, actual agent model, then an enabled model from an enabled provider. It does not fabricate capabilities. The initial no-POST observation was also affected by the separately recorded early-Enter fixture boundary in BUG147; it alone does not prove model resolution caused a failed request.
- **Fixture-only final assertion:** After the Location fix both modes completed a real prompt and approval, made two provider calls, and created exactly one Session at the requested directory. The newly authored final assertion then accessed legacy `message.info.role` on native messages. It was corrected to the canonical `message.type` discriminator; this was not a product failure or another recurrence.
- **Verification:** From packages/apexo, `bun script/grok-native-terminal-fresh.mjs` and `bun script/grok-native-terminal-fresh.mjs --fullscreen` each passed 2 checks / 2 provider calls. Both asserted exactly one Session at the attached resolved Location and exactly one canonical user message after actual terminal prompt and Question approval. All PTYs and fixture servers were reaped.
