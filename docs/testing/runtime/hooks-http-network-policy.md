# BUG-20261014-107: Host HTTP hooks lacked the reference transport policy

- **Scope:** Host HTTP hooks in shared Core dispatch; installed plugin-bundle transport remains separate.
- **Observed:** Static comparison found that host hooks accepted cleartext HTTP and private network destinations. The initial redirect restriction and response cap did not implement the reference's address policy.
- **Expected:** Require HTTPS, permit loopback, reject private/link-local/unspecified/CGNAT destinations including mapped IPv4, validate every DNS result, and never follow redirects. TLS verification must remain enabled.
- **Reference:** Pinned `xai-grok-hooks/src/runner/http.rs` address validation and HTTP client construction; `xai-grok-extra-ca/src/lib.rs` extra CA selection and size limit.
- **Reproduction:** Configure a host HTTP hook using a cleartext loopback URL or a private literal destination. Compare validation with a trusted HTTPS loopback hook.
- **Root cause:** The initial shared fetch path validated only URL scheme membership and redirects; it had no host-hook-specific network boundary.
- **Fix:** Add an Apexo-owned HTTPS transport with standard IP range checks and DNS validation. Host-global GROK_EXTRA_CA_BUNDLE overrides SSL_CERT_FILE; an explicit empty primary value disables fallback. Extra roots are bounded to 1 MiB and invalid certificates are skipped. Default roots remain enabled and certificate verification is never disabled. Existing host transport tests now use a dedicated public test CA and leaf certificate.
- **Limits:** Validation is at DNS resolution time; transport can resolve again, so DNS rebinding is not prevented. Runtime default trust stores and extra-root refresh timing are not claimed identical to the reference's Rust process cache. This is not a command sandbox.
- **Verification:** Focused network/host/environment/Stop/observer suite passed 21 tests / 107 assertions. Tests include IPv4/IPv6/mapped ranges, real localhost resolution, extra-root precedence and bounds, trusted TLS success, untrusted certificate rejection, redirect non-following, output cap, and unchanged hook decision/observer semantics. CLI passed five scenarios and package typecheck passed. The strengthened CLI diagnostic assertions passed, and the isolated installed comparator passed all 18 scenarios. The refreshed production Desktop artifact passed all five scenarios. The expanded related batch (host/environment/network/observer/Stop, durable Session Stop, permission, and tool tests) passed 107 tests / 256 assertions. The first installed comparison failed its cleartext-rejection assertion: installed Grok 1.0.52 allows loopback HTTP, unlike the pinned source HTTPS-only rule. Its diagnostic explicitly refused the private address at load time. The comparator now records that difference; Apexo keeps the pinned source policy at dispatch. This observed expectation mismatch is part of the same contract audit, not an additional historical occurrence.
- **Occurrences:** One static contract finding; no historical count is inferred.
