# Memory Retrieval Ranking

## BUG-20261014-035 — Full-text relevance omitted retrieval ranking signals

- **Status:** Implemented and verified on CLI, packaged Desktop, unit tests, and pinned official legacy source; installed official V2 retrieval comparison also passed.
- **Verified recurrence count:** 0. Static feature-gap finding from code inspection; no pre-fix execution or historical recurrence is claimed.
- **Scope:** Core MemorySearch; Grok Build `memory_search`; initial/recovery memory retrieval through MemoryIndex.
- **Observed:** Search normalized BM25 and immediately truncated results. Old session notes had no temporal penalty or staleness hint; repeated retrieval did not affect later ranking; redundant notes crowded out diverse results; configured source weights were unavailable.
- **Expected:** Follow the pinned official legacy retrieval pipeline: evergreen supplementation, session-only exponential decay, source multipliers, persistent logarithmic access boost, raw-score ordering before display clamping, then normalized Jaccard MMR before truncation. Evergreen global/workspace sources do not decay or show staleness warnings.
- **Reproduction:** Index identical workspace and session notes, age their persisted creation timestamps by 30 days, then search with minimum score zero. Previously both displayed full relevance. Retrieve one of two identical notes before adding the second; previously the access did not break their tie. Add a distinct third note and set MMR lambda to zero; previously configuration could not diversify results.
- **Root cause:** The initial FTS-only implementation had no persisted chunk ranking metadata, scoring configuration, or post-relevance reranking.
- **Fix:** Added `memory.search` settings, durable creation/access metadata with upgrade backfill and removal cleanup, supplemental evergreen candidates, official decay/source/access scoring, MMR, and session staleness hints. Successful search results increment access counts. Creation times and access survive ordinary reindexing. Session MemoryIndex reads configured settings. Existing authorization and maintenance revision checks remain ahead of result delivery.
