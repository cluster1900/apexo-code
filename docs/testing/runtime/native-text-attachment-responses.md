# BUG-20261015-257: Native text attachment is unsupported by Responses conversion

- Status: repaired and integrated; shared focused verification, builds and actual compiled CLI/packaged Desktop conversion acceptance pass.
- Scope: a `text/plain` file on the native Session path using the configured `xai/grok-4.7` model and OpenAI Responses adapter.

The real native headless attach fixture admitted an explicit UTF-8 file as a canonical file part with a text/plain data URI. The input reached the runner but failed before any outbound provider request. The canonical failed step reported `OpenAI Responses does not support media type text/plain`; the input outcome was failed/provider_error with incomplete usage. The CLI returned exit 1 and preserved that error and receipt.

This proves a specific native file-to-provider conversion limitation. It does not prove that every attachment is unsupported, and it does not justify removing image support or silently dropping a file. The CLI keeps canonical admission and existing provider validation. The original acceptance case recorded the actual failure and zero outbound calls; a separate valid PNG case requires its image data URI in the real provider request and a completed outcome.

Reproduce with `bun script/grok-native-headless.mjs --attach` using the fixture's actual configured provider/model. The first text-file success expectation failed after the argv issue was corrected. The ordered repair changes only native Session history lowering and its two callers. Canonical text/plain base64 data URIs become ordinary user text with a JSON-escaped filename/description header and exact UTF-8 body. It accepts the explicit UTF-8 charset form, strictly validates canonical base64 and UTF-8, limits each file to 10 MiB decoded and cumulative selected text history to 20 MiB, and rejects remote/file/raw-base64 text URIs. It neither reads a file nor fetches a URL, changes durable attachments or permission checks, widens provider media MIME allowlists, nor adds another provider loop. Main-run failures retain the typed provider_error input receipt; side-question snapshot failures map to the existing safe invalid error before a side row is created.
