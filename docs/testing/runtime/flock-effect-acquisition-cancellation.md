# BUG-20261015-326: Scoped file-lock acquisition masked cancellation

- Scope: Canonical `Flock.effect`, including native Memory maintenance/capture/Dream and model-catalog locks.
- Observed: A waiting Effect acquire could not be interrupted until the current holder released its lock. Its Options.signal was also overwritten by an Effect signal generated inside uninterruptible acquisition.
- Expected: Cancellation aborts and joins the actual pending acquire. If acquisition wins the race, cleanup releases that exact lease once before completing. Normal scope lifetime, timeout and dead-owner policy remain intact.
- Root cause: Effect.acquireRelease masks its acquisition; the acquire Promise's Effect AbortSignal therefore never received interruption during the wait. Earlier Memory tests could cancel before acquisition started and did not prove the actual held-lock boundary.
- Fix: Own the acquisition Promise in one scoped, uninterruptible child with a dedicated AbortController combined with an optional caller signal. Restore interruption only while waiting for that child's Exit. Interruption aborts and joins it, releasing an acquired lease if necessary. Successful acquisition registers scoped release while masked, closing the ownership gap.
- Reproduction: Hold a real lock; use its real onWait callback to prove a second acquire is waiting, then cancel without releasing the holder. A controlled onWait gate separately proves that cancellation cannot report completion while the underlying acquire callback remains pending.
- Verification: Before the production change, four shared tests produced two passes and two failures: both waiting-cancellation cases exceeded their one-second observation window. After the change, all four cases passed in the shared Memory gate, including caller-signal cancellation, normal reacquisition, bounded timeout and the late-acquired-lease race. Three existing real dead-owner/mutual-exclusion tests also passed. The 72-test gate had 70 passes and two unrelated HTTP fixture route failures; the corrected HTTP hosts and broader Memory health/capture/Dream ownership checks subsequently pass in a 54-test / 495-assertion gate. All 21 workspace typechecks pass. Run `bun test --timeout 30000 test/util/flock-effect-interruption.test.ts test/util/flock-dead-owner.test.ts` from packages/apexo for the lock regression.
- Independent occurrences: One confirmed canonical defect discovered through automatic Memory validation. Multiple affected consumers are not separate recurrences. No rule is promoted.

The late-acquire race uses an isolated child that wraps only the result of a real acquisition, counts release calls and then reacquires the real lock. It does not mock shared globals or replace filesystem ownership. The test observes cancellation with the existing poll helper, releasing its holder before checking a negative result so the before-fix control cannot strand cleanup.

This correction is separate from [bounded readiness persistence after acquisition](native-memory-maintenance-recovery-ownership.md). Neither fix establishes the unrelated CLI subprocess timeout cause.
