# INVESTIGATION-20261014-001: Goal Full-Suite Regression Timeout

- **Status**: Investigating; root cause unconfirmed.
- **Scope**: Goal HTTP lifecycle, concurrent creation, catalog reading, and background subtask integration tests.
- **Observed**: Full-suite runs occasionally timed out on the 5-second test deadline (e.g., 4 failures out of 315 tests, or 1 failure in Goal HTTP lifecycle at ~6.4s) when run concurrently with builds, typechecks, or E2E suites.
- **Expected**: Complete within the 5-second deadline without relaxing assertions or hiding failures.
- **Reproduction Command**: In `packages/apexo`, run `GITHUB_ACTIONS=false bun test test/session/goal-files.test.ts test/session/goal.test.ts test/session/prompt.test.ts test/session/tools.test.ts test/session/llm-native.test.ts test/server/httpapi-goal.test.ts test/effect/runtime-flags.test.ts test/config/config.test.ts`.
- **Investigation Notes**: Added `APEXO_TEST_GOAL_TIMING=1` diagnostics to separate service initialization from request execution. Sequential reruns of the same 9-file and 11-file suites passed (320/320 and 332/332, with the lifecycle request phase taking 192 ms and total test time 1.16 s), and all three `test:httpapi` modes passed (232/232 each). Kept as `Investigating` because a passing sequential rerun does not prove the root cause of the earlier timeouts.

2026-10-14 cleanup stage: a five-file run passed 153 tests with one existing skip and one failure. The concurrent-creation HTTP test exceeded the existing five-second deadline (5565.73 ms); the other three HTTP tests took 4136, 3571, and 4457 ms. Build/typecheck processes were running, but the run lacked stage timings, so load is not a proven cause. After the detached-job regression was added, a sequential run with the same deadlines passed 155 tests, one existing skip, zero failures, and 888 assertions in 57.78 seconds. All three HTTP API gate modes also passed 232 checks each. These results leave the root-cause investigation open.

2026-10-14 parallel feature stage: a 13-file run completed with 236 passes, one existing skip, and three five-second deadline failures: Goal HTTP lifecycle (5012 ms), waiting for a background child (5008 ms), and continuing after a rejected completion (5179 ms). Official Rust compilation and a Desktop build overlapped that run. The HTTP request-phase diagnostic was about 602 ms at the deadline and continued afterwards; this does not establish where all preceding time was spent. Running those same three cases separately passed all three with 24 assertions in 8.62 seconds, without changing deadlines.

A subsequent frozen-source run, with no overlapping Rust or Desktop build, passed 242 tests, one existing skip, zero failures, and 1253 assertions across the same 13 files in 61.58 seconds. Reproduction from `packages/apexo`: `GITHUB_ACTIONS=false APEXO_TEST_GOAL_TIMING=1 bun test test/tool/grok-shell-config.test.ts test/tool/grok-build-background.test.ts test/tool/grok-build.test.ts test/tool/grok-build-extensions.test.ts test/tool/grok-build-media.test.ts test/tool/registry.test.ts test/tool/memory-search.test.ts test/tool/memory-ranking.test.ts test/session/goal-cleanup.test.ts test/session/goal-reports.test.ts test/server/httpapi-goal.test.ts test/session/goal.test.ts test/session/prompt.test.ts`.

**Still unresolved:** these comparisons suggest checking scheduling and fixture initialization under load, but neither a root cause nor a product fix has been established. Keep this investigation open. Do not count these symptoms as repeated occurrences of a confirmed root cause, promote a constraint, or present the passing reruns as a fix.
